# Pro 2 资源更新前端交互示例

## 1. 设计目标

前端提供足够细的状态反馈，但不依赖资源实际拆成多少个文件，也不感知 `vol0:/...` 等设备内部路径。

建议围绕稳定逻辑分组展示：基础界面、语言资源、字体资源、动画资源、壁纸资源和启动资源。

## 2. 检查阶段

```text
┌──────────────────────────────────────────┐
│ 更新设备资源                             │
│                                          │
│ 正在检查设备需要的资源…                  │
│                                          │
│ 连接方式：USB                            │
│ 当前资源：2026.06.28                     │
│                                          │
│                                  取消    │
└──────────────────────────────────────────┘
```

这个阶段对应 SDK 获取目标 Manifest、设备验证 Manifest 和设备生成更新计划。前端不展示“正在比较文件路径”等实现细节。

## 3. 更新计划确认

```text
┌──────────────────────────────────────────┐
│ 发现新的资源更新                         │
│                                          │
│ 资源版本：2026.07.16                     │
│ 完整资源：126.4 MB                       │
│ 本次传输：  8.4 MB                       │
│ 已复用：  118.0 MB                       │
│                                          │
│ ✓ 基础界面                 已是最新       │
│ ● 语言资源                 需要更新       │
│ ✓ 字体资源                 已是最新       │
│ ● 动画与壁纸               需要更新       │
│                                          │
│              稍后更新      开始更新       │
└──────────────────────────────────────────┘
```

这里突出显示实际传输量，让用户看到增量更新收益。如果资源更新是主固件升级的一部分，可以把计划摘要合并到固件升级确认页。

## 4. 下载和传输阶段

```text
┌──────────────────────────────────────────┐
│ 正在更新设备资源                         │
│                                          │
│ ████████████████░░░░░░░░░░       61%    │
│                                          │
│ ✓ 基础界面                 已是最新       │
│ ✓ 语言资源                 更新完成       │
│ ● 动画与壁纸               3.1 / 5.4 MB   │
│ ○ 启动资源                 等待中         │
│                                          │
│ 已传输 5.1 / 8.4 MB                      │
│ 速度 842 KB/s                            │
│                                          │
│ 请保持设备连接                           │
└──────────────────────────────────────────┘
```

内部应区分 CDN 下载、传输到设备和设备验证，但默认界面可以统一显示为“正在更新”，仅在诊断信息中保留细阶段。

## 5. BLE 断开和恢复

```text
┌──────────────────────────────────────────┐
│ 连接已中断                               │
│                                          │
│ 已完成的数据不会丢失。                   │
│ 请重新连接设备，我们将继续更新。         │
│                                          │
│ 上次进度：5.1 / 8.4 MB                   │
│                                          │
│                              重新连接    │
└──────────────────────────────────────────┘
```

重连后 SDK 查询设备 session：

- session 仍存在：按设备返回的 artifact 和绝对偏移继续。
- session 已过期：重新 Prepare；已验证对象会显示为 `PRESENT`，不会重复传输。

## 6. 验证和提交

```text
┌──────────────────────────────────────────┐
│ 正在验证资源                             │
│                                          │
│ 设备正在检查资源完整性和签名。           │
│ 此过程通常需要几秒钟。                   │
│                                          │
│ █████████████████████████░░       92%    │
│                                          │
│ 请勿断开设备                             │
└──────────────────────────────────────────┘
```

Commit 阶段即使发生断开，也不能提示“设备资源可能损坏”。旧 Manifest 在成功切换前一直有效。

## 7. 完成

```text
┌──────────────────────────────────────────┐
│ 资源更新完成                             │
│                                          │
│ 已更新到 2026.07.16                      │
│                                          │
│ 本次传输：8.4 MB                         │
│ 节省流量：118.0 MB                       │
│                                          │
│                                  完成    │
└──────────────────────────────────────────┘
```

如果需要重启，展示“设备将自动重启并检查新资源，请保持连接”。完成状态必须来自设备健康确认，而不是上传达到 100%。

## 8. 自动回滚

```text
┌──────────────────────────────────────────┐
│ 新资源未能正常启动                       │
│                                          │
│ 设备已自动恢复到之前的资源版本。         │
│ 钱包和设备数据不受影响。                 │
│                                          │
│ 错误编号：RESOURCE_HEALTH_CHECK_FAILED   │
│                                          │
│                    查看详情      完成    │
└──────────────────────────────────────────┘
```

不要只显示“更新失败”，需要明确告诉用户已经安全回滚。

## 9. 空间不足

```text
┌──────────────────────────────────────────┐
│ 设备存储空间不足                         │
│                                          │
│ 本次更新需要：18.2 MB                    │
│ 当前可用空间：11.6 MB                    │
│ 可安全清理：9.4 MB                       │
│                                          │
│ 清理内容仅包括未使用的旧资源。           │
│                                          │
│                    取消      清理并重试  │
└──────────────────────────────────────────┘
```

设备只能清理不被 current/previous Manifest 引用的对象。SDK 和前端不能直接传入删除路径。

## 10. 分组聚合规则

| artifact 状态                  | 分组状态       |
| ------------------------------ | -------------- |
| 全部 `PRESENT`                 | `upToDate`     |
| 存在等待项且没有活动项         | `waiting`      |
| 任一 artifact 正在下载         | `downloading`  |
| 任一 artifact 正在设备传输     | `transferring` |
| 任一 artifact 正在验证         | `verifying`    |
| 全部为 `PRESENT` 或 `VERIFIED` | `completed`    |
| 任一不可恢复失败               | `failed`       |

总进度建议分配：下载和传输 0%～ 85%，artifact 验证 85%～ 95%，Commit 和健康检查 95%～ 100%。前端不能因为上传完成就直接显示 100%。

## 11. 文案建议

推荐：

- “正在检查设备需要的资源”
- “只会传输有变化的内容”
- “已完成的数据不会丢失”
- “设备正在验证资源完整性”
- “设备已安全恢复到之前的资源版本”

避免：

- “正在写入 vol0:/bundles”
- “正在安装第 3 个文件”
- “资源包数量不匹配”
- “覆盖设备文件失败”

物理文件和路径只出现在诊断日志中。
