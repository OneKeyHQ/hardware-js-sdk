# Multisig Test 执行区域布局优化设计

## 背景

当前 `MultisigExecutionPanel` 使用等高双栏布局：左侧展示设备交互信息，右侧展示执行结果。两侧内容密度和生命周期并不对称，导致执行前左侧拥挤、右侧空旷，执行按钮也被弱化在分区标题中。

## 目标

- 让“执行测试”成为右侧工作区明确的主操作。
- 执行前快速核对设备信息，执行后优先阅读结果或错误。
- 减少嵌套滚动和低高度屏幕下的内容挤压。
- 保持现有状态、数据和执行逻辑不变。

## 布局方案

`MultisigExecutionPanel` 改为上下两层：

1. 顶部执行栏：左侧显示设备交互标题、说明和就绪状态；右侧放置主执行按钮。
2. 中部核对区：测试助记词警告、执行摘要和设备核对项使用紧凑的响应式网格展示。
3. 底部结果区：占满可用宽度，标题、耗时和状态内容归入同一结果容器。

桌面端摘要根据宽度自动分为多列；窄屏降为单列。结果区在 idle、running、error、success 四种状态下保持一致的外框和空间分配。

## 视觉层级

- 主操作：执行按钮。
- 次级状态：可执行、未连接、参数错误、等待设备。
- 辅助信息：设备摘要、核对项和测试助记词警告。
- 输出焦点：地址、签名、已签交易或错误信息。

不引入新的渐变、阴影或装饰性色彩，继续沿用现有 `Button`、`Badge`、`Alert` 和主题 token。

## 状态与错误处理

- 不修改 `MultisigExecutionState`、校验条件或硬件调用。
- running 状态继续禁止重复执行，并显示设备确认提示。
- error 状态继续使用 warning Alert。
- success 状态继续以可滚动的等宽 JSON 内容展示。

## 验证

- 更新布局回归测试，验证执行区不再使用左右双栏结构。
- 运行 Multisig 相关 Jest 测试、ESLint 和 expo-playground 生产构建。
- 人工检查宽屏和窄屏下的主操作、摘要和结果区层级。
