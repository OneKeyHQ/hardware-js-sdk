# Multisig Test 设备连接入口调整设计

## 背景

当前 `Multisig Test` 页面将未连接设备提示和“搜索设备”操作放在底部“设备交互”面板中。设备连接是整个测试页面的前置条件，而不是某一个测试用例的执行结果，因此当前入口层级过低，用户需要滚动到页面底部才能建立连接，并且连接提示占用了请求摘要区域。

## 目标

- 将设备搜索与连接提示提升为页面级入口。
- 用户进入页面后无需滚动即可发现“搜索设备”操作。
- 保持底部执行区域聚焦于请求核对、执行状态和设备确认。
- 不修改设备搜索、自动连接和 SDK 方法执行逻辑。

## 非目标

- 不重做设备管理流程或搜索弹窗。
- 不修改全局导航栏、传输方式切换或设备状态存储。
- 不改变多签用例、参数校验、签名方法和结果展示。
- 不新增持久显示的已连接设备详情面板。

## 页面结构

页面从上到下调整为：

1. `Multisig Test` 面包屑标题。
2. 页面级设备连接提示；仅在未连接设备时显示。
3. 用例库、参数编辑器和底部执行面板组成的工作区。

设备连接提示复用现有 `DeviceNotConnectedState`，放在标题与工作区之间。设备连接成功后，组件根据全局设备状态返回空内容，提示条自动消失，不保留空白占位。

## 执行面板调整

底部 `MultisigExecutionPanel` 移除内嵌的 `DeviceNotConnectedState`，继续保留：

- “已连接 / 未连接 / Local”状态标签。
- “执行测试 / 本地校验”按钮。
- SDK 方法、地址、金额等请求摘要。
- 设备屏幕核对事项。
- 运行中、成功和错误结果。

未连接设备时，执行按钮仍由现有 `canExecute` 条件禁用。页面级提示负责解释原因并提供搜索入口，避免在执行面板重复展示相同信息。

## 响应式与视觉要求

- 连接提示横跨页面工作区宽度，位于面包屑下方，保持现有紧凑工具型视觉。
- 桌面和窄屏均保持“先连接、再选择或编辑、最后执行”的阅读顺序。
- 不新增装饰性卡片或动画，沿用现有明暗主题、按钮和告警色。
- 连接提示出现时允许工作区压缩，但不得遮挡用例列表或参数编辑区域。

## 状态与数据流

```text
MultisigTestPage 读取全局 currentDevice
        ↓ 未连接
页面顶部显示 DeviceNotConnectedState
        ↓ 搜索并自动连接
全局 currentDevice 更新
        ↓
顶部提示自动消失，执行按钮解除连接条件禁用
```

本次调整只移动现有组件的渲染位置，不复制搜索逻辑，也不新增局部连接状态。

## 验证标准

- 未连接设备时，页面标题下方可以直接看到“搜索设备”入口。
- 底部“设备交互”区域不再出现设备连接提示卡片。
- 未连接时“执行测试”按钮仍不可用。
- 连接成功后顶部提示自动消失，“已连接”状态和执行能力正确更新。
- 本地校验用例不要求连接设备，仍可直接执行。
- 页面在桌面和窄屏下没有溢出、遮挡或不可访问操作。

## 测试策略

- 运行 `expo-playground` 相关 TypeScript 类型检查或构建检查。
- 运行 Multisig 相关单元测试，确认执行条件和用例逻辑未受影响。
- 浏览器人工验证未连接、已连接和本地校验三种状态。
