# 阶段性设计与实施计划

本目录保留既有的设计讨论和实施计划，便于理解复杂改动的历史背景。

## 使用边界

- 本目录不是当前技术事实源，内容可能引用已经变化的分支、文件、消息名、验证命令或
  尚未实现的方案。
- 判断当前行为时，优先读取代码、生成源和 [`docs/README.md`](../README.md) 列出的长期
  维护文档。
- `specs/` 记录某一阶段的设计输入和取舍。
- `plans/` 记录某一阶段的实施顺序、目标文件和验证设想。
- 不要因为历史计划要求某项操作，就直接移动子模块、安装固件、修改设备或执行发布。

## 维护方式

历史文件原则上保持原样。设计结论成为长期约束时，应更新对应的架构、协议、设备、SDK
或业务文档，并通过 Git 历史关联原始计划。

新的短期计划优先保存在 PR、Issue 或提交历史中。只有跨仓库、跨阶段且确有长期追溯价值
的材料才考虑放入本目录，并且不得替代长期事实文档。
