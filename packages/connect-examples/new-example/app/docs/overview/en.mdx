## Overview & Architecture

The OneKey SDK is a monorepo project that provides a unified suite of tools for communicating with OneKey hardware wallets across different platforms (Web, Desktop, Mobile). Its core design philosophy is to offer a unified and simplified API that automatically handles complex low-level communication protocols, allowing developers to focus on business logic.

**Integration Flow:**
1. **Choose the appropriate transport** for your platform and environment (WebUSB, HTTP(JSBridge/Bridge), BLE, HID, Lowlevel, etc.).
2. **Select the corresponding SDK**:
   - `@onekeyfe/hd-web-sdk` for Web/Desktop
   - `@onekeyfe/hd-ble-sdk` for React Native
   - `@onekeyfe/hd-common-connect-sdk` for Native Mobile (with manual transport selection)

### Architecture Explained

- **Application Layer**: Your application (Web, React Native, or Native Mobile) depending on your target platform.
- **SDK Layer**: OneKey provides three core SDK packages, each optimized for a specific development environment:
  - `@onekeyfe/hd-web-sdk`: For browsers and web-based desktop applications (like Electron). Handles both **WebUSB** and **JSBridge** communication methods.
  - `@onekeyfe/hd-ble-sdk`: For **React Native** applications, used for communicating with hardware via Bluetooth (BLE).
  - `@onekeyfe/hd-common-connect-sdk`: A generic package suitable for **native mobile applications (iOS/Android)**. It can handle BLE, HTTP(JSBridge), and low-level transports.
- **Transport Layer**: Low-level modules that implement direct communication with the hardware. The SDK automatically selects or allows you to specify the most suitable transport method:
  - `@onekeyfe/hd-transport-webusb`
  - `@onekeyfe/hd-transport-http`
  - `@onekeyfe/hd-transport-ble`
  - `@onekeyfe/hd-transport-hid`
  - `@onekeyfe/hd-transport-lowlevel`
- **Protocol Layer**: Protobuf Protocol (unified message encoding/decoding)
- **Hardware Layer**: OneKey Hardware

> For more details, see the [official OneKey Hardware SDK documentation](https://developer.onekey.so/connect-to-hardware/page-1/started)
