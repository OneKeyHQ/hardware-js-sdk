import { HardwareSDK, UI_EVENT } from '@onekeyfe/hd-web-sdk';

## Core Concepts

To ensure robust integration with OneKey hardware, you must understand the following core concepts:

---

### Event Handling

The OneKey SDK uses an event-driven model for user interactions (PIN, Passphrase, etc). Your app **must** listen for and respond to these events, or hardware operations will time out.

**Recommended:** Set up global event listeners at app initialization.

- `UI_EVENT.REQUEST_PIN`: Hardware requests PIN. Show a PIN entry UI.
- `UI_EVENT.REQUEST_PASSPHRASE`: Hardware requests Passphrase. Show a Passphrase entry UI.
- `DEVICE.CONNECT` / `DEVICE.DISCONNECT`: Device connection state changes.

**Example:**

```ts
HardwareSDK.on(UI_EVENT.REQUEST_PIN, async (device, callback) => {
  const pin = await showPinDialog();
  callback(null, pin);
});

HardwareSDK.on(UI_EVENT.REQUEST_PASSPHRASE, async (device, callback) => {
  const passphrase = await showPassphraseDialog();
  callback(null, passphrase);
});
```

---

### Passphrase (BIP39 Passphrase)

A Passphrase is an extra password (BIP39 standard) that creates a new "hidden wallet". The same mnemonic with different passphrases derives different accounts.

- **Security:** If you forget the passphrase, you cannot recover the hidden wallet.
- Use an empty passphrase for the main wallet if you don't need this feature.

#### `passphrase` vs. `passphraseState`

- `passphrase`: String, used for a **single** API call. Not cached.
- `passphraseState`: Encrypted state from the device, reusable for up to 10 minutes (cached by SDK).
- `getPassphraseState` requires a `passphrase` and returns a `passphraseState`. If both are provided, `passphraseState` is used.

**Example:**

```ts
const userPassphrase = await showPassphraseDialog();
const state = await HardwareSDK.getPassphraseState({ passphrase: userPassphrase });
const address = await HardwareSDK.evmGetAddress({
  path: "m/44'/60'/0'/0/0",
  passphraseState: state,
});
```

---

### PIN Handling

- PIN unlocks the device. Any signing operation on a locked device triggers a PIN request.
- **On-device entry:** Touch/Pro models require PIN entry on device (no `REQUEST_PIN` event).
- **Client-side entry:** Classic/Mini models require PIN entry in your app (SDK emits `UI_EVENT.REQUEST_PIN`).

**Example:**

```ts
HardwareSDK.on(UI_EVENT.REQUEST_PIN, (device, callback) => {
  if (!device.features?.pin_protection_always_on_device) {
    const pin = await showPinDialog();
    callback(null, pin);
  } else {
    showUserNotification('Please enter your PIN on the OneKey device.');
    callback(null, '');
  }
});
```
