# evmSignTransaction

<span id="ethereum-sign-transaction" />

Demandez une signature confirmée sur l’appareil pour une transaction historique ou EIP-1559 (Type 2). L’appareil dérive la clé depuis votre chemin BIP32 ; votre application sérialise et diffuse le résultat. Les détails décodés de la transaction dépendent du micrologiciel et du calldata.

```typescript
const result = await HardwareSDK.evmSignTransaction(connectId, deviceId, params);
```

## Avant l’appel [#before-you-call]

- [Initialiser le SDK et sélectionner un appareil](/fr/hardware-sdk/getting-started).
- Enregistrez les [gestionnaires d’événements d’interface](/fr/hardware-sdk/core-api-guide#events-ui) et sélectionnez explicitement le portefeuille souhaité.
- Récupérez les valeurs actuelles de nonce, de gas et de frais depuis le réseau cible.

### Champs de transaction [#transaction-fields]

| Champ | Type | Description |
| --- | --- | --- |
| `chainId` | `number` | ID de chaîne du réseau cible. Se trouve dans transaction. |
| `to` | `string` | Adresse de destination ; le contrat du jeton pour les appels ERC-20. |
| `value` | `string` | Montant en wei encodé en hexadécimal. Utilisez 0x0 pour les appels ERC-20. |
| `nonce` | `string` | Nombre de transactions du compte expéditeur, sous forme de quantité hexadécimale. |
| `gasLimit` | `string` | Limite de gas, sous forme de quantité hexadécimale. |
| `data` | `string · optional` | Calldata complet encodé en hexadécimal ; utilisez 0x en l’absence de calldata. |
| `maxFeePerGas` | `string · EIP-1559` | Frais totaux maximaux par unité de gas, en wei encodés en hexadécimal. |
| `maxPriorityFeePerGas` | `string · EIP-1559` | Frais de priorité maximaux par unité de gas, en wei encodés en hexadécimal. |
| `gasPrice` | `string · Legacy` | Prix du gas historique, en wei encodés en hexadécimal. |

Cette page couvre `EVMTransaction` et `EVMTransactionEIP1559`. Consultez [Chemins HD](/fr/hardware-sdk/concepts/common-params#hd-path) pour le format des chemins. Assurez-vous que votre RPC cible prend en charge le type de transaction.

EIP-1559 nécessite les deux champs de frais ; le format historique utilise `gasPrice`. Ne transmettez pas `type: 2` au SDK ; sélectionnez le type lors de la sérialisation de la transaction signée.

## Clear Signing [#clear-signing]

Utilisez cette même méthode pour les transferts natifs, les transferts ERC-20, les autorisations/révocations et les appels de contrat. Pour les appels ERC-20, `to` est le contrat du jeton et `value` vaut zéro ; le calldata contient le destinataire/bénéficiaire autorisé et le montant du jeton. Un micrologiciel compatible décode automatiquement les formats reconnus. Il n’existe aucun paramètre `clearSigning`, de métadonnées de jeton ou de libellé de contrat.

Consultez le [guide Clear Signing](/fr/hardware-sdk/signers/evm#clear-signing) pour la matrice des entrées/affichages et le comportement face aux contrats inconnus. Pour EIP-712 et les signatures de propriétaires Safe, utilisez [evmSignTypedData](/fr/hardware-sdk/chains/ethereum-and-evm/evmsigntypeddata).

## Sérialiser la transaction signée [#serialize-the-signed-transaction]

Le SDK renvoie une signature ; votre application assemble et diffuse la transaction. Cet exemple utilise les paquets ethers v5. Conservez les champs de transaction d’origine inchangés après la signature de l’utilisateur.

```typescript
import type { UnsignedTransaction } from '@ethersproject/transactions';
import { TransactionTypes, serialize } from '@ethersproject/transactions';
import { splitSignature } from '@ethersproject/bytes';
import { keccak256 } from '@ethersproject/keccak256';

// Illustrative fee values: populate nonce, gas, and fees from your network.
const transaction = {
  to: '0x7314e0f1c0e28474bdb6be3e2c3e0453255188f8',
  value: '0x0',
  data: '0x',
  chainId: 1,
  nonce: '0x0',
  maxFeePerGas: '0x14',
  maxPriorityFeePerGas: '0x0',
  gasLimit: '0x5208',
};

const result = await HardwareSDK.evmSignTransaction(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  transaction,
});
if (result.success === false) throw new Error(result.payload.error);

const unsignedTx: UnsignedTransaction = {
  ...transaction,
  nonce: Number.parseInt(transaction.nonce, 16),
  type: TransactionTypes.eip1559,
};
const signature = splitSignature({
  v: Number(result.payload.v),
  r: result.payload.r,
  s: result.payload.s,
});
const rawTx = serialize(unsignedTx, signature);
const txid = keccak256(rawTx);
// Submit rawTx using your Ethereum provider after verifying the signed result.
```

Pour une transaction historique, utilisez `gasPrice` à la place des deux champs de frais EIP-1559 et sérialisez-la comme une transaction historique.
