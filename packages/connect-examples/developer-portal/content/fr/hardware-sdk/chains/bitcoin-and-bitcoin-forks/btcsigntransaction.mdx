# btcSignTransaction

## Bitcoin : signer une transaction [#bitcoin-sign-transaction]

Demande les signatures des entrées et sorties d’une transaction préparée. L’utilisateur vérifie et confirme la demande sur l’appareil.

```typescript
const result = await HardwareSDK.btcSignTransaction(connectId, deviceId, params);
```

## Paramètres [#params]

[**Paramètres communs facultatifs**](/fr/hardware-sdk/concepts/common-params)

* `coin` - _obligatoire_ `string` Détermine la définition du réseau spécifiée dans [bitcoin.json](https://github.com/OneKeyHQ/hardware-js-sdk/blob/onekey/packages/core/src/data/coins/bitcoin.json). Les champs `shortcut`, `name` ou `label` de la monnaie peuvent être utilisés.
* `inputs` - _obligatoire_ `Array` de [TxInputType](https://github.com/OneKeyHQ/hardware-js-sdk/blob/728279dc70c5bde56c5d72d86598815f977b0c7f/packages/hd-transport/src/types/messages.ts#L363),
* `outputs` - _obligatoire_ `Array` de [TxOutputType](https://github.com/OneKeyHQ/hardware-js-sdk/blob/728279dc70c5bde56c5d72d86598815f977b0c7f/packages/hd-transport/src/types/messages.ts#L390),
* `refTxs` - _obligatoire_ `Array` de [RefTransaction](https://github.com/OneKeyHQ/hardware-js-sdk/blob/728279dc70c5bde56c5d72d86598815f977b0c7f/packages/core/src/types/api/btcSignTransaction.ts#L26). Les refTxs Zcash et Komodo doivent également contenir les champs `expiry`, `version_group_id` et `extra_data`.
* `locktime` - _facultatif_ `number`,
* `version` - _facultatif_ `number` version de transaction,
* `expiry` - _facultatif_ `number`, uniquement pour Decred et Zcash,
* `versionGroupId` - _facultatif_ `number` uniquement pour Zcash, nVersionGroupId lorsque overwintered est défini,
* `overwintered` - _facultatif_ `boolean` uniquement pour Zcash
* `timestamp` - _facultatif_ `number` uniquement pour Capricoin, horodatage de transaction,
* `branchId` - _facultatif_ `number`, uniquement pour Zcash, BRANCH\_ID lorsque overwintered est défini

## Construire les paramètres de transaction [#build-transaction-parameters]

### Construire une entrée [#build-an-input]

```
const buildHardwareInput = async (
  input: TxInput,
  path: string,
): Promise<Messages.TxInputType> => {
  const { getHDPath, getScriptType } = await CoreSDKLoader();
  const addressN = getHDPath(path);
  const scriptType = getScriptType(addressN);
  const utxo = input.utxo as UTXO;

    return {
    prev_index: utxo.vout,
    prev_hash: utxo.txid,
    amount: utxo.value.integerValue().toString(),
    address_n: addressN,
    script_type: scriptType,
  };
};
```

### Construire une sortie [#build-an-output]

```
const buildHardwareOutput = async (
  output: TxOutput,
): Promise<Messages.TxOutputType> => {
  const { isCharge, bip44Path } = output.payload || {};

  if (isCharge && bip44Path) {
    const { getHDPath, getOutputScriptType } = await CoreSDKLoader();
    const addressN = getHDPath(bip44Path);
    const scriptType = getOutputScriptType(addressN);
    return {
      script_type: scriptType,
      address_n: addressN,
      amount: output.value.integerValue().toString(),
    };
  }

  return {
    script_type: 'PAYTOADDRESS',
    address: output.address,
    amount: output.value.integerValue().toString(),
  };
};
```

### Construire une transaction précédente [#build-a-previous-transaction]

```
import * as BitcoinJS from 'bitcoinjs-lib';
const buildPrevTx = (rawTx: string): RefTransaction => {
    const tx = BitcoinJS.Transaction.fromHex(rawTx);

    return {
      hash: tx.getId(),
      version: tx.version,
      inputs: tx.ins.map((i) => ({
        prev_hash: Buffer.from(i.hash).reverse().toString('hex'),
        prev_index: i.index,
        script_sig: Buffer.from(i.script).toString('hex'),
        sequence: i.sequence,
      })),
      bin_outputs: tx.outs.map((o) => ({
        amount: o.value.toString(),
        script_pubkey: Buffer.from(o.script).toString('hex'),
      })),
      lock_time: tx.locktime,
    };
  };
```

## Exemple [#example]

Les extraits ci-dessous illustrent les structures des paramètres. Utilisez des UTXO réellement dépensables, des montants correspondants et des transactions précédentes complètes ; les données statiques ne constituent pas une transaction prête à être diffusée.

### PAYTOADDRESS [#paytoaddress]

```typescript
import type { BTCSignTransactionParams } from "@onekeyfe/hd-core";

// Load the actual previous transactions for the UTXOs below.
declare const refTxs: BTCSignTransactionParams["refTxs"];
declare const previousOutputAmount: string;

HardwareSDK.btcSignTransaction(connectId, deviceId, {
    inputs: [
        {
            address_n: [(44 | 0x80000000) >>> 0, (0 | 0x80000000) >>> 0, (2 | 0x80000000) >>> 0, 1, 0],
            prev_index: 0,
            prev_hash: 'b035d89d4543ce5713c553d69431698116a822c57c03ddacf3f04b763d1999ac',
            amount: previousOutputAmount,
        }
    ],
    outputs: [
        {
            address_n: [(44 | 0x80000000) >>> 0, (0 | 0x80000000) >>> 0, (2 | 0x80000000) >>> 0, 1, 1],
            amount: '3181747',
            script_type: 'PAYTOADDRESS',
        }, {
            address: '18WL2iZKmpDYWk1oFavJapdLALxwSjcSk2',
            amount: '200000',
            script_type: 'PAYTOADDRESS',
        }
    ],
    refTxs,
    coin: 'btc'
});
```

### Résultat [#result]

```typescript
{
    success: true,
    payload: {
        signatures: Array<string>, // Array of signer signatures
        serializedTx: string,        // serialized transaction
        txid?: string,             // transaction ID, if returned; signing does not broadcast
    }
}
```

Erreur

```typescript
{
    success: false,
    payload: {
        error: string, // error message
        code?: string | number // error code
    }
}
```
