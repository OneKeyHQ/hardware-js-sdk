# btcDeriveContextHash

Dérivez sur l’appareil un hachage de contexte Babylon de 32 octets pour la clé Bitcoin, l’application, le contexte et le réseau sélectionnés. La réponse contient un `secret` sensible destiné à votre application.

Disponible dans le SDK `1.2.8-alpha.6`. Nécessite **Classic 1s ou Classic 1s Pure avec un micrologiciel 3.21.0 ou ultérieur** et **Protocol V1**. Les autres familles d’appareils et Protocol V2 ne sont pas pris en charge.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, params);
```

## Avant l’appel [#before-you-call]

- [Initialisez le SDK et sélectionnez un appareil](/fr/hardware-sdk/getting-started).
- Enregistrez les [gestionnaires d’événements d’interface](/fr/hardware-sdk/core-api-guide#events-ui) et sélectionnez explicitement la [session de portefeuille](/fr/hardware-sdk/concepts/wallet-session) souhaitée.
- Avant l’appel, obtenez l’accord de l’utilisateur pour l’application demandeuse et son origine. `appName` est fourni par l’appelant ; votre application doit déterminer quel site ou quelle application demande l’accès.

## Exemple [#example]

Ce fragment suppose que le SDK est initialisé et qu’un portefeuille standard est sélectionné. Remplacez les valeurs d’exemple `path`, `appName`, `context` et `network` par celles approuvées par l’utilisateur. Le contexte ci-dessous est un exemple de données encodées en hexadécimal.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, {
  path: "m/84'/0'/0'/0/0",
  appName: 'babylon-example',
  context: '48656c6c6f',
  network: 'bitcoin-mainnet',
  useEmptyPassphrase: true,
});

if (result.success === false) throw new Error(result.payload.error);
const secret = result.payload.secret;
// Use only for the approved application and context. Do not log or persist it.
```

L’exemple sélectionne explicitement le portefeuille standard avec `useEmptyPassphrase: true`. Pour un portefeuille caché, transmettez le même `passphraseState` que lors de la confirmation du compte Bitcoin connecté. Le parcours habituel de PIN, de passphrase et de confirmation sur l’appareil reste applicable.

## Réponse [#result]

## Gestion des erreurs et du secret [#errors-and-secret-handling]

Une valeur invalide de `path`, `appName`, `context` ou `network` renvoie `CallMethodInvalidParameter` (`405`) avant l’envoi de la commande de dérivation. Les familles d’appareils non prises en charge ou Protocol V2 renvoient `DeviceNotSupportMethod` (`415`) ; un micrologiciel antérieur à 3.21.0 nécessite une mise à jour.

L’annulation sur l’appareil renvoie la réponse standard `success: false`. Arrêtez la requête et traitez `payload.error` et `payload.code` avant de tenter un nouvel appel.

Le SDK renvoie le véritable `secret` à votre application. Traitez-le comme une donnée sensible : excluez-le des journaux, de la télémétrie, du presse-papiers et du stockage persistant. La dérivation s’exécute sur l’appareil ; la clé interne du portefeuille n’est pas exportée.
