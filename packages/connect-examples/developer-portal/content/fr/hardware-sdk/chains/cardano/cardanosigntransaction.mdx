# cardanoSignTransaction

## Exigences [#requirements]

* Versions minimales du micrologiciel
  * Touch : 4.1.0
  * Classic/Mini : 3.0.0

### Cardano : signer une transaction <a href="#cardano-sign-transaction" id="cardano-sign-transaction"></a> [#cardano-sign-transaction-]

Demande une signature de transaction. L’utilisateur vérifie et confirme la demande sur l’appareil.

```javascript
const response = await HardwareSDK.cardanoSignTransaction(connectId, deviceId, params);
```

### Paramètres <a href="#params" id="params"></a> [#params-]

[Paramètres communs facultatifs](/fr/hardware-sdk/concepts/common-params)

Type CardanoSignTransaction

* `signingMode` - _obligatoire_ CardanoTxSigningMode
* `inputs` - _obligatoire_ `Array` de CardanoInput
* `outputs` - _obligatoire_ `Array` de CardanoOutput
* `fee` - _obligatoire_ `String`
* `protocolMagic` - _obligatoire_ `Integer` 764824073 pour Mainnet, 1 pour Preprod Testnet, 2 pour Preview Testnet
* `networkId` - _obligatoire_ `Integer` 1 pour Mainnet, 0 pour Testnet
* `ttl` - _facultatif_ `String`
* `validityIntervalStart` - _facultatif_ `String`
* `certificates` - _facultatif_ `Array` de CardanoCertificate
* `withdrawals` - _facultatif_ `Array` de CardanoWithdrawal
* `auxiliaryData` - _facultatif_ CardanoAuxiliaryData
* `mint` - _facultatif_ CardanoMint
* `scriptDataHash` - _facultatif_ `String`
* `collateralInputs` - _facultatif_ `Array` de CardanoCollateralInput
* `requiredSigners` - _facultatif_ `Array` de CardanoRequiredSigner
* `collateralReturn` - _facultatif_ CardanoOutput
* `totalCollateral` - _facultatif_ `String`
* `referenceInputs` - _facultatif_ `Array` de CardanoReferenceInput
* `additionalWitnessRequests` - _facultatif_ `Array` de `string | Array<number>` (chemins). Utilisé pour les demandes de témoins de multisignature et de création de jetons, car ils ne peuvent pas être déterminés à partir des paramètres de transaction.
* `metadata` - _supprimé_ - utiliser `auxiliaryData` à la place
* `derivationType` - _facultatif_ énumération `CardanoDerivationType`. Détermine le type de dérivation utilisé. La valeur par défaut est ICARUS=1.
* `includeNetworkId` - _facultatif_ `Boolean`. Détermine si `networkId` doit être explicitement sérialisé dans le corps de la transaction. La valeur par défaut est `false`.

#### CardanoTxSigningMode <a href="#cardanotxsigningmode" id="cardanotxsigningmode"></a> [#cardanotxsigningmode-]

**`ORDINARY_TRANSACTION`**

Représente une transaction utilisateur ordinaire transférant des fonds, déléguant du stake ou retirant des récompenses. Les témoins de la transaction proviennent des clés dérivées des chemins inclus dans `inputs`, `certificates` et `withdrawals`. De plus, si la transaction crée des jetons, ses témoins proviendront aussi des clés dérivées des chemins inclus dans `additionalWitnessRequests`.

La transaction

* _doit_ avoir une propriété valide `path` sur tous les éléments `inputs`
* _ne doit pas_ contenir de certificat d’enregistrement de pool
* _ne doit pas_ contenir `collateralInputs`, `collateralReturn`, `totalCollateral` et `referenceInputs`
* _doit_ contenir des chemins comme identifiants de staking dans les certificats et retraits (pas de hashes de clés ni de scripts)
* _peut_ contenir uniquement des chemins 1852 et 1855
* _ne doit pas_ contenir des demandes de témoins 1855 lorsque la transaction ne crée ni ne détruit de jetons

#### Particularités des certificats d’enregistrement de pool de staking <a href="#stake-pool-registration-certificate-specifics" id="stake-pool-registration-certificate-specifics"></a> [#stake-pool-registration-certificate-specifics-]

OneKey prend en charge la signature de certificats d’enregistrement de pool de staking en tant que propriétaire du pool. La transaction peut contenir des entrées externes (par exemple appartenant à l’opérateur du pool), et OneKey ne peut pas vérifier si elles sont réellement externes. Autoriser la signature de la transaction avec une clé de dépense présenterait donc un risque de perte de fonds depuis une entrée que l’utilisateur ne souhaitait pas dépenser. Il existe aussi un risque de signer involontairement un retrait inclus dans la transaction. Pour atténuer ces risques, nous avons introduit des règles de validation spécifiques aux transactions d’enregistrement de pool de staking, également vérifiées sur OneKey. Ces règles sont les suivantes :

1. La transaction ne doit contenir aucun autre certificat, pas même un autre enregistrement de pool de staking
2. La transaction ne doit contenir aucun retrait
3. Les entrées de la transaction doivent toutes être externes, c’est-à-dire que path doit valoir undefined ou null
4. Un seul propriétaire doit être transmis sous forme de chemin de staking, et tous les autres sous forme d’adresses de récompense encodées en bech32

#### Enregistrement de gouvernance (Catalyst et autres) <a href="#governance-registration-catalyst-and-other" id="governance-registration-catalyst-and-other"></a> [#governance-registration-catalyst-and-other-]

OneKey prend en charge la signature de transactions dont les données auxiliaires contiennent un enregistrement de gouvernance. Ces enregistrements suivaient auparavant [CIP-15](https://cips.cardano.org/cips/cip15/), qui a été remplacé par [CIP-36](https://cips.cardano.org/cips/cip36/). OneKey prend actuellement en charge les formats CIP-15 et CIP-36 ; la norme souhaitée peut être spécifiée dans le champ `format` (avec CIP-15 par défaut). Ils diffèrent sur les points suivants :

* CIP-36 permet de déléguer le pouvoir de vote à plusieurs clés publiques de vote avec des pondérations différentes (CardanoCVoteRegistrationDelegation), au lieu de fournir une seule clé publique de vote. Le micrologiciel OneKey prend en charge au maximum 32 délégations dans un seul enregistrement de gouvernance.
* Les enregistrements CIP-36 contiennent le champ votingPurpose. La valeur 0 est destinée au vote Catalyst et la valeur 1 à d’autres usages. Si aucune valeur n’est fournie, OneKey sérialise 0 par défaut (si le format CIP-36 est utilisé).

OneKey ne prend actuellement pas en charge les chemins de dérivation 1694.

#### Résultat <a href="#result" id="result"></a> [#result-]

Depuis l’introduction du streaming de transactions dans l’implémentation Cardano de OneKey pour des contraintes mémoire, OneKey ne renvoie plus l’intégralité de la transaction sérialisée en résultat de l’appel `CardanoSignTransaction`. À la place, il renvoie le hash de transaction, les témoins de transaction et le complément de données auxiliaires ; le client doit assembler la transaction sérialisée.

Type CardanoSignedTxData

```javascript
{
    success: true,
    payload: {
        hash: string,
        witnesses: CardanoSignedTxWitness[],
        auxiliaryDataSupplement?: CardanoAuxiliaryDataSupplement,
    }
}
```
