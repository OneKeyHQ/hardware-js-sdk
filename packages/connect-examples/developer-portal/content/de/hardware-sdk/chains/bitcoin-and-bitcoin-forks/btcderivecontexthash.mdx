# btcDeriveContextHash

Leiten Sie auf dem Gerät einen 32-Byte-Babylon-Kontexthash für den ausgewählten Bitcoin-Schlüssel, die Anwendung, den Kontext und das Netzwerk ab. Die Antwort enthält einen sensiblen `secret`-Wert zur Verwendung in Ihrer Anwendung.

Verfügbar im SDK `1.2.8-alpha.6`. Erfordert **Classic 1s oder Classic 1s Pure mit Firmware 3.21.0 oder neuer** und **Protocol V1**. Andere Gerätefamilien und Protocol V2 werden nicht unterstützt.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, params);
```

## Vor dem Aufruf [#before-you-call]

- [Initialisieren Sie das SDK und wählen Sie ein Gerät aus](/de/hardware-sdk/getting-started).
- Registrieren Sie [UI-Ereignishandler](/de/hardware-sdk/core-api-guide#events-ui) und wählen Sie die gewünschte [Wallet-Sitzung](/de/hardware-sdk/concepts/wallet-session) ausdrücklich aus.
- Holen Sie vor dem Aufruf die Zustimmung des Benutzers für die anfragende Anwendung und deren Ursprung ein. `appName` wird vom Aufrufer angegeben; Ihre Anwendung muss feststellen, welche Website oder Anwendung Zugriff anfordert.

## Beispiel [#example]

Dieses Fragment setzt ein initialisiertes SDK und eine ausgewählte Standard-Wallet voraus. Ersetzen Sie die Beispielwerte `path`, `appName`, `context` und `network` durch die vom Benutzer genehmigten Werte. Der folgende Kontext ist ein Beispiel für hexadezimal kodierte Daten.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, {
  path: "m/84'/0'/0'/0/0",
  appName: 'babylon-example',
  context: '48656c6c6f',
  network: 'bitcoin-mainnet',
  useEmptyPassphrase: true,
});

if (result.success === false) throw new Error(result.payload.error);
const secret = result.payload.secret;
// Use only for the approved application and context. Do not log or persist it.
```

Das Beispiel wählt mit `useEmptyPassphrase: true` ausdrücklich die Standard-Wallet aus. Übergeben Sie für eine versteckte Wallet denselben `passphraseState`, der bei der Bestätigung des verbundenen Bitcoin-Kontos verwendet wurde. Der normale Ablauf für PIN, Passphrase und Gerätebestätigung gilt weiterhin.

## Fehler und Umgang mit dem Secret [#errors-and-secret-handling]

Ein ungültiger Wert für `path`, `appName`, `context` oder `network` führt vor dem Senden des Ableitungsbefehls zu `CallMethodInvalidParameter` (`405`). Nicht unterstützte Gerätefamilien oder Protocol V2 führen zu `DeviceNotSupportMethod` (`415`); Firmware unter 3.21.0 muss aktualisiert werden.

Ein Abbruch am Gerät liefert die Standardantwort `success: false`. Beenden Sie die Anfrage und behandeln Sie `payload.error` und `payload.code`, bevor Sie einen weiteren Aufruf versuchen.

Das SDK gibt den tatsächlichen `secret`-Wert an Ihre Anwendung zurück. Behandeln Sie ihn als sensibel: Halten Sie ihn aus Protokollen, Telemetrie, Zwischenablage und dauerhaftem Speicher fern. Die Ableitung läuft auf dem Gerät; der interne Wallet-Schlüssel wird nicht exportiert.
