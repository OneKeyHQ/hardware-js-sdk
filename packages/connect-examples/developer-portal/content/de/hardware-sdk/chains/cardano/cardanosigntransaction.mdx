# cardanoSignTransaction

## Voraussetzungen [#requirements]

* Mindest-Firmware-Versionen
  * Touch: 4.1.0
  * Classic/Mini: 3.0.0

### Cardano: Transaktion signieren <a href="#cardano-sign-transaction" id="cardano-sign-transaction"></a> [#cardano-sign-transaction-]

Fordert eine Transaktionssignatur an. Der Nutzer prüft und bestätigt die Anfrage auf dem Gerät.

```javascript
const response = await HardwareSDK.cardanoSignTransaction(connectId, deviceId, params);
```

### Parameter <a href="#params" id="params"></a> [#params-]

[Optionale gemeinsame Parameter](/de/hardware-sdk/concepts/common-params)

CardanoSignTransaction-Typ

* `signingMode` - _erforderlich_ CardanoTxSigningMode
* `inputs` - _erforderlich_ `Array` von CardanoInput
* `outputs` - _erforderlich_ `Array` von CardanoOutput
* `fee` - _erforderlich_ `String`
* `protocolMagic` - _erforderlich_ `Integer` 764824073 für Mainnet, 1 für Preprod Testnet, 2 für Preview Testnet
* `networkId` - _erforderlich_ `Integer` 1 für Mainnet, 0 für Testnet
* `ttl` - _optional_ `String`
* `validityIntervalStart` - _optional_ `String`
* `certificates` - _optional_ `Array` von CardanoCertificate
* `withdrawals` - _optional_ `Array` von CardanoWithdrawal
* `auxiliaryData` - _optional_ CardanoAuxiliaryData
* `mint` - _optional_ CardanoMint
* `scriptDataHash` - _optional_ `String`
* `collateralInputs` - _optional_ `Array` von CardanoCollateralInput
* `requiredSigners` - _optional_ `Array` von CardanoRequiredSigner
* `collateralReturn` - _optional_ CardanoOutput
* `totalCollateral` - _optional_ `String`
* `referenceInputs` - _optional_ `Array` von CardanoReferenceInput
* `additionalWitnessRequests` - _optional_ `Array` von `string | Array<number>` (Pfade). Für Witness-Anfragen bei Multisig und Token-Prägung verwendet, da diese nicht aus den Transaktionsparametern ermittelt werden können.
* `metadata` - _entfernt_ - verwenden Sie `auxiliaryData` stattdessen
* `derivationType` - _optional_ `CardanoDerivationType`-Enum. Bestimmt den verwendeten Ableitungstyp. Standard ist ICARUS=1.
* `includeNetworkId` - _optional_ `Boolean`. Bestimmt, ob `networkId` ausdrücklich in den Transaktionskörper serialisiert werden soll. Standard ist `false`.

#### CardanoTxSigningMode <a href="#cardanotxsigningmode" id="cardanotxsigningmode"></a> [#cardanotxsigningmode-]

**`ORDINARY_TRANSACTION`**

Stellt eine gewöhnliche Nutzertransaktion dar, die Gelder überträgt, Stake delegiert oder Belohnungen abhebt. Die Witnesses der Transaktion werden mit Schlüsseln erzeugt, die aus den in `inputs`, `certificates` und `withdrawals` angegebenen Pfaden abgeleitet werden. Wenn Token-Prägung enthalten ist, werden zusätzliche Witnesses mit Schlüsseln erzeugt, die aus den Pfaden in `additionalWitnessRequests` abgeleitet werden.

Die Transaktion

* _sollte_ eine gültige `path`-Eigenschaft auf allen `inputs` enthalten
* _darf nicht_ ein Pool-Registrierungszertifikat enthalten
* _darf nicht_ enthalten `collateralInputs`, `collateralReturn`, `totalCollateral` und `referenceInputs`
* _muss_ Pfade als Stake-Zugangsdaten in Zertifikaten und Abhebungen enthalten (keine Schlüssel- oder Skripthashes)
* _darf_ nur 1852- und 1855-Pfade enthalten
* _darf nicht_ 1855-Witness-Anfragen enthalten, wenn die Transaktion keine Tokens prägt/verbrennt

#### Besonderheiten bei Stake-Pool-Registrierungszertifikaten <a href="#stake-pool-registration-certificate-specifics" id="stake-pool-registration-certificate-specifics"></a> [#stake-pool-registration-certificate-specifics-]

OneKey unterstützt das Signieren von Stake-Pool-Registrierungszertifikaten als Pool-Eigentümer. Die Transaktion kann externe Eingaben enthalten (z. B. des Pool-Betreibers), und OneKey kann nicht prüfen, ob sie tatsächlich extern sind. Würden wir das Signieren mit einem Ausgabeschlüssel erlauben, bestünde daher das Risiko, Gelder aus einer Eingabe zu verlieren, die der Nutzer nicht ausgeben wollte. Außerdem besteht das Risiko, versehentlich eine gegebenenfalls enthaltene Abhebung zu signieren. Um diese Risiken zu verringern, haben wir spezielle Validierungsregeln für Stake-Pool-Registrierungstransaktionen eingeführt, die auch auf OneKey geprüft werden. Die Regeln lauten:

1. Die Transaktion darf keine anderen Zertifikate enthalten, auch keine weitere Stake-Pool-Registrierung
2. Die Transaktion darf keine Abhebungen enthalten
3. Alle Transaktionseingaben müssen extern sein, d. h. path muss entweder undefined oder null sein
4. Genau ein Eigentümer sollte als Staking-Pfad und die übrigen Eigentümer als bech32-kodierte Belohnungsadressen übergeben werden

#### Governance-Registrierung (Catalyst und andere) <a href="#governance-registration-catalyst-and-other" id="governance-registration-catalyst-and-other"></a> [#governance-registration-catalyst-and-other-]

OneKey unterstützt das Signieren von Transaktionen mit Zusatzdaten, die eine Governance-Registrierung enthalten. Governance-Registrierungen folgten früher [CIP-15](https://cips.cardano.org/cips/cip15/), das ersetzt wurde durch [CIP-36](https://cips.cardano.org/cips/cip36/). Derzeit unterstützt OneKey sowohl CIP-15- als auch CIP-36-Formate; der vorgesehene Standard kann angegeben werden im `format`-Feld (wobei CIP-15 der Standard ist). Die Unterschiede sind:

* CIP-36 erlaubt, die Stimmgewalt auf mehrere öffentliche Abstimmungsschlüssel mit unterschiedlicher Stimmgewalt zu delegieren (CardanoCVoteRegistrationDelegation), statt nur einen einzelnen öffentlichen Abstimmungsschlüssel anzugeben. Beachten Sie, dass die OneKey-Firmware höchstens 32 Delegationen in einer einzelnen Governance-Registrierung unterstützt.
* CIP-36-Registrierungen enthalten das Feld votingPurpose. Der Wert 0 ist für Catalyst-Abstimmungen vorgesehen, der Wert 1 für andere Zwecke. Wird kein Wert angegeben, serialisiert OneKey standardmäßig 0 (wenn das CIP-36-Format verwendet wird).

OneKey unterstützt derzeit keine 1694-Ableitungspfade.

#### Ergebnis <a href="#result" id="result"></a> [#result-]

Seit wegen Speicherbeschränkungen Transaktions-Streaming in der Cardano-Implementierung von OneKey eingeführt wurde, gibt OneKey nicht mehr die gesamte serialisierte Transaktion als Ergebnis des `CardanoSignTransaction`-Aufrufs zurück. Stattdessen werden Transaktionshash, Transaktions-Witnesses und Zusatzdatenergänzung zurückgegeben; der Client muss die serialisierte Transaktion zusammensetzen.

CardanoSignedTxData-Typ

```javascript
{
    success: true,
    payload: {
        hash: string,
        witnesses: CardanoSignedTxWitness[],
        auxiliaryDataSupplement?: CardanoAuxiliaryDataSupplement,
    }
}
```
