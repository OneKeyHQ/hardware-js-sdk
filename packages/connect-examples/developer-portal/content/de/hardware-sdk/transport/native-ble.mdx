# Natives BLE

Verwenden Sie `@onekeyfe/hd-common-connect-sdk` in einem nativen mobilen Kontext, um Hardware-Transportaufrufe über BLE weiterzuleiten. Das SDK führt JavaScript in einer WebView oder JS-Engine aus, während die native Bluetooth-Kommunikation in der Host-App erfolgt.

## Wann natives BLE wählen [#when-to-choose-native-ble]

- Sie steuern das gesamte native App-Erlebnis (Android, iOS, Flutter) und können eine WebView oder JS-Laufzeit bereitstellen, die `send`/`receive` über BLE weiterleitet.
- Sie benötigen detaillierten Zugriff auf BLE-Berechtigungen des Betriebssystems, Kopplungsabläufe oder eine eigene Oberfläche, die in Swift/Kotlin oder Flutter einfacher als in React Native zu entwickeln ist.
- Sie möchten die `@onekeyfe/hd-common-connect-sdk`-JavaScript-API wiederverwenden und dabei den nativen BLE-Stack selbst verwalten.

## Grundbegriffe [#core-concepts]

- Lesen Sie [Low-Level-Transport-Plugin &amp; Protokoll](/de/hardware-sdk/concepts/low-level-plugin) vor der Anbindung von nativem BLE, um die Weiterleitung roher BLE-Benachrichtigungen und die vom SDK verwaltete V1-/V2-Rahmung zu verstehen.
- Abonnieren Sie frühzeitig `UI_EVENT`, damit PIN-/Passphrase-Bestätigungen und Aufforderungen die Anfragewarteschlange nicht blockieren.
- Verwenden Sie denselben `HardwareSDK`-Adapter wie in der Web-Anleitung; der native Code leitet lediglich BLE-Pakete statt WebUSB weiter.
