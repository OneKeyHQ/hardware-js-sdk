# 署名者ガイド

チェーンごとに初期化から署名済みトランザクションまでを段階的に説明します。先に[リクエストの基本](/ja/hardware-sdk/core-api-guide#request-basics)を読んでください。

## 構成 [#structure]

- 前提条件: ファームウェア/SDK バージョン、必要なトランスポート、デバイス確認
- 手順: 接続 → アカウントパスを選択 → リクエストを構築 → デバイスで確認 → 結果を検証
- 統合用コード: リクエストパラメーターと結果検証。アプリの UI、ネットワークデータ、トランザクション入力はホストが提供
- FAQ: パス違い、拒否/タイムアウト、ネットワークやデータの問題

## 簡易チェックリスト (署名前に確認) [#quick-checklist-read-before-any-signer]

- 環境とバージョン: 最新ファームウェア + バージョンを揃えた SDK/Bridge。プラットフォーム用のトランスポートガイドを選択します。
- パス: チェーン固有の HD パスを使用し、ハード化/非ハード化を再確認します (各署名者ページを参照)。
- セッションとウォレット: 多くのチェーンメソッドには `connectId + deviceId` が必要です (BLE では `deviceId` が必須)。`deviceId` はリセット後に変わります。隠しウォレットの場合は `passphraseState` を含めてください。
- UI: `UI_EVENT` を購読し、PIN/パスフレーズのプロンプトを `uiResponse` で処理します。
- 結果の検証: 必ず `success` を確認してから、チェーンのライブラリで返されたアドレス/署名を検証します。
- 安全性: 予期しないプロンプトは拒否し、デバイスが Bootloader の場合は即座に失敗させます。

## 利用可能なガイド [#available-guides]

- [EVM 署名者](./evm) — パス、EIP-1559 と Legacy のパラメーター、デバイスのプロンプト、署名後のブロードキャスト; [クリアサイニング](./evm#clear-signing) — 送金、承認/取り消し、トークン/コントラクト、EIP-712、Safe Tx
- [BTC 署名者](./btc) — スクリプト/パス対応表、refTx の完全性、お釣り/出力の確認、シリアライズ
- [Solana 署名者](./solana) — 固定のハード化パス、生メッセージ/トランザクションの準備、署名の組み立て
