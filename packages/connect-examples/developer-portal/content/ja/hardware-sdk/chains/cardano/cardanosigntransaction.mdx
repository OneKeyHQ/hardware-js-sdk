# cardanoSignTransaction

## 要件 [#requirements]

* 最小ファームウェアバージョン
  * Touch: 4.1.0
  * Classic/Mini: 3.0.0

### Cardano: トランザクションに署名 <a href="#cardano-sign-transaction" id="cardano-sign-transaction"></a> [#cardano-sign-transaction-]

トランザクションの署名を要求します。ユーザーはデバイス上でリクエストを確認して承認します。

```javascript
const response = await HardwareSDK.cardanoSignTransaction(connectId, deviceId, params);
```

### パラメーター <a href="#params" id="params"></a> [#params-]

[任意の共通パラメーター](/ja/hardware-sdk/concepts/common-params)

CardanoSignTransaction 型

* `signingMode` - _必須_ CardanoTxSigningMode
* `inputs` - _必須_ CardanoInput の `Array`
* `outputs` - _必須_ CardanoOutput の `Array`
* `fee` - _必須_ `String`
* `protocolMagic` - _必須_ `Integer` メインネットは 764824073、Preprod テストネットは 1、Preview テストネットは 2
* `networkId` - _必須_ `Integer` メインネットは 1、テストネットは 0
* `ttl` - _任意_ `String`
* `validityIntervalStart` - _任意_ `String`
* `certificates` - _任意_ CardanoCertificate の `Array`
* `withdrawals` - _任意_ CardanoWithdrawal の `Array`
* `auxiliaryData` - _任意_ CardanoAuxiliaryData
* `mint` - _任意_ CardanoMint
* `scriptDataHash` - _任意_ `String`
* `collateralInputs` - _任意_ CardanoCollateralInput の `Array`
* `requiredSigners` - _任意_ CardanoRequiredSigner の `Array`
* `collateralReturn` - _任意_ CardanoOutput
* `totalCollateral` - _任意_ `String`
* `referenceInputs` - _任意_ CardanoReferenceInput の `Array`
* `additionalWitnessRequests` - _任意_ `string | Array<number>` (パス) の `Array`。マルチシグおよびトークン発行のウィットネス要求に使用します。これらはトランザクションのパラメーターから決定できないためです。
* `metadata` - _削除済み_ - 代わりに `auxiliaryData` を使用
* `derivationType` - _任意_ `CardanoDerivationType` 列挙型。使用する導出タイプを決定します。デフォルトは ICARUS=1。
* `includeNetworkId` - _任意_ `Boolean`。`networkId` をトランザクション本体に明示的にシリアライズするかどうかを指定します。デフォルトは `false`。

#### CardanoTxSigningMode <a href="#cardanotxsigningmode" id="cardanotxsigningmode"></a> [#cardanotxsigningmode-]

**`ORDINARY_TRANSACTION`**

資金の送金、ステークの委任、報酬の引き出しを行う通常のユーザートランザクションを表します。`inputs`、`certificates`、`withdrawals` に含まれるパスから導出した鍵でウィットネスを作成します。また、トークン発行を含む場合は、`additionalWitnessRequests` に含まれるパスから導出した鍵でもウィットネスを作成します。

トランザクションは

* _推奨:_ すべての `inputs` に有効な `path` プロパティを指定すること
* _禁止:_ プール登録証明書を含めること
* `collateralInputs`、`collateralReturn`、`totalCollateral`、`referenceInputs` を含めることは_禁止_されています
* _必須:_ 証明書と引き出しのステーク認証情報にパスを含めること (キーハッシュやスクリプトハッシュは不可)
* _許可:_ 1852 と 1855 のパスのみを含めること
* _禁止:_ トークンの発行/バーンを行わないトランザクションに 1855 のウィットネス要求を含めること

#### ステークプール登録証明書の詳細 <a href="#stake-pool-registration-certificate-specifics" id="stake-pool-registration-certificate-specifics"></a> [#stake-pool-registration-certificate-specifics-]

OneKey は、プール所有者としてステークプール登録証明書に署名できます。トランザクションには外部の入力 (プール運営者のものなど) が含まれる可能性があり、OneKey はそれが本当に外部の入力かを検証できません。そのため、支出用の鍵での署名を許可すると、ユーザーが支出を意図しなかった入力から資金を失うリスクがあります。また、引き出しが含まれている場合に、意図せず署名するリスクもあります。これらを軽減するため、ステークプール登録トランザクションには特別な検証ルールを設け、OneKey 上でも検証します。ルールは次のとおりです:

1. トランザクションに他の証明書を含めてはいけません。別のステークプール登録も不可です
2. トランザクションに引き出しを含めてはいけません
3. 入力はすべて外部のものとし、path は undefined または null でなければなりません
4. 所有者のうち正確に 1 人をステーキングパスで渡し、残りは bech32 エンコードされた報酬アドレスで渡してください

#### ガバナンス登録 (Catalyst など) <a href="#governance-registration-catalyst-and-other" id="governance-registration-catalyst-and-other"></a> [#governance-registration-catalyst-and-other-]

OneKey はガバナンス登録を含む補助データ付きトランザクションへの署名に対応しています。ガバナンス登録は以前 [CIP-15](https://cips.cardano.org/cips/cip15/) に従っていましたが、現在は [CIP-36](https://cips.cardano.org/cips/cip36/) に置き換えられています。現在、OneKey は CIP-15 と CIP-36 の両形式に対応し、目的の標準を `format` フィールドで指定できます (デフォルトは CIP-15)。相違点は次のとおりです:

* CIP-36 では、投票公開鍵を 1 つだけ指定する代わりに、異なる投票力を持つ複数の投票公開鍵へ委任できます (CardanoCVoteRegistrationDelegation)。OneKey ファームウェアが 1 件のガバナンス登録で対応する委任は最大 32 件です。
* CIP-36 の登録には votingPurpose フィールドが含まれます。0 は Catalyst 投票用、1 はその他の用途です。値を指定しない場合、OneKey はデフォルトで 0 をシリアライズします (CIP-36 形式の場合)。

現在、OneKey は 1694 の導出パスに対応していません。

#### 結果 <a href="#result" id="result"></a> [#result-]

メモリー制約により OneKey の Cardano 実装にトランザクションのストリーミングが導入されたため、`CardanoSignTransaction` の呼び出し結果として、シリアライズ済みトランザクション全体は返されなくなりました。代わりに、トランザクションハッシュ、ウィットネス、補助データの追加情報が返されます。クライアント側でシリアライズ済みトランザクションを組み立てる必要があります。

CardanoSignedTxData 型

```javascript
{
    success: true,
    payload: {
        hash: string,
        witnesses: CardanoSignedTxWitness[],
        auxiliaryDataSupplement?: CardanoAuxiliaryDataSupplement,
    }
}
```
