# 用語集

これらの用語は OneKey のウォレットおよびハードウェア統合ガイドに登場します。形式や動作はブロックチェーンごとに異なるため、統合対象チェーンのリファレンスに従ってください。

## ウォレット [#wallet]

鍵を管理し、アカウントの表示や操作の承認を支援するアプリケーションまたはデバイス。資産とトランザクションの状態はブロックチェーンに記録され、ウォレットアプリ内に保存されるわけではありません。

## アカウント [#account]

関連する状態を持つブロックチェーン上の識別情報。Ethereum では外部所有アカウントは秘密鍵、コントラクトアカウントはコードで制御されます。すべてのアカウントが公開鍵/秘密鍵のペアではありません。

## アドレス [#address]

資産の受け取りや、アカウント/コントラクトの操作に使う識別子。Ethereum アドレスは 20 バイトで、通常は `0x` に 40 桁の 16 進数を続けて表記します。アドレスと公開鍵は別物です。

## 公開鍵 [#public-key]

暗号鍵ペアの公開部分。署名の検証や、チェーンによってはアドレスの導出に使います。エンコード方式と長さは署名方式と形式によって異なります。

## 秘密鍵 [#private-key]

署名によって操作を承認する秘密情報。dApp、統合フォーム、ログ、Issue 報告に秘密鍵を貼り付けるようユーザーに求めてはいけません。

## リカバリーフレーズ [#recovery-phrase]

ウォレットが鍵を導出する元の情報をバックアップするための単語列。BIP-39 はニーモニックフレーズとシードへの変換を定義します。フレーズは秘密情報として扱い、統合フローで要求しないでください。

## シード [#seed]

階層的な鍵導出への入力。BIP-39 では、ニーモニックと任意のパスフレーズからシードを導出します。単一アカウントの秘密鍵とは置き換えられません。

## 導出パス [#derivation-path]

階層型ウォレット内の鍵を識別するインデックス列。チェーン、アカウント、アドレスタイプ、お釣りの分岐によってパスが変わります。統合するメソッドとチェーンが想定するパスを使用してください。

## パスフレーズ [#passphrase]

リカバリーフレーズと組み合わせて別のウォレットを導出する任意の値。パスフレーズが異なると別のウォレットになる場合があります。デバイス PIN の別名ではありません。

## PIN [#pin]

ハードウェアデバイスへのアクセスを保護するコード。リカバリーフレーズやパスフレーズとは異なります。SDK が提供するデバイス別の PIN フローに従ってください。

## プロバイダー [#provider]

dApp がウォレットにアカウント、ブロックチェーン情報、署名を要求する JavaScript インターフェース。Ethereum プロバイダーは一般に EIP-1193 に従い、他のチェーンは別のインターフェースを使います。

## トランスポート [#transport]

USB や Bluetooth など、デバイスとデータを交換する接続。トランスポートが動作しても、それだけでアカウントへのアクセスや署名が許可されるわけではありません。

## 署名とブロードキャスト [#signature-and-broadcast]

署名は鍵でメッセージやトランザクションを承認する操作です。ブロードキャストは署名済みトランザクションをネットワークに送信する操作です。両者は別の操作なので、対象 API が署名だけを行うのか、送信も行うのか確認してください。

## エアギャップ [#air-gap]

署名デバイスとアプリケーションの間に直接の有線/無線接続を持たない通信フロー。QR 統合ではリクエストとレスポンスを QR データとして交換します。トランザクションのブロードキャストには、アプリ側のネットワーク接続が引き続き必要です。

## キーストア [#keystore]

鍵情報と、その復号に必要なパラメーターを暗号化して表現したもの。保護の強さは暗号化設定とパスワードに依存し、暗号化データに共通の固定長はありません。

## 16 進数 [#hexadecimal]

数字の `0–9` と文字の `a–f` を使う 16 進表記です。API によって、`0x` プレフィックスの付加または省略が必要な場合や、代わりにバイト列を受け付ける場合があります。各パラメーターで指定されたエンコード方式に従ってください。
