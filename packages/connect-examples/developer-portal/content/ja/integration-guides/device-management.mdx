# デバイスの設定と消去

デバイス管理は、通常のアカウント検出や署名とは別です。ユーザーが意図的に開始する、明確に識別された管理フローでのみ提供してください。初回接続時にデバイスを自動で初期化・消去してはいけません。

## deviceReset: デバイスにウォレットを作成 [#devicereset-create-a-wallet-on-a-device]

`deviceReset(connectId, params)` はデバイス設定と新しい復元情報の生成を要求します。現在の SDK 実装は Protocol V1 を使用し、V2 対応を宣言していません。メソッド名から Pro 2 対応を推測しないでください。

| パラメーター | 型 | 意味 |
| --- | --- | --- |
| `displayRandom` | `boolean` | 追加エントロピーを要求する前に、デバイスが生成したエントロピーを表示。 |
| `strength` | `number` | 要求するエントロピー強度。SDK のフォールバック値は `256`; 受け付ける強度はファームウェアにも依存します。 |
| `pinProtection`, `passphraseProtection` | `boolean` | 要求する保護設定。 |
| `language`, `label` | `string` | 要求するデバイスの言語とラベル。 |
| `u2fCounter` | `number` | U2F カウンター。SDK のフォールバック値は現在の Unix タイムスタンプ (秒)。 |
| `skipBackup`, `noBackup` | `boolean` | バックアップフローのオプション。どちらもデバイスにシードがないことを意味しません。黙って有効化しないでください。 |
| `backupType` | `string \| number` | ファームウェアに依存するバックアップ形式。 |

これらのオプションは公開型では任意です。対象ファームウェアを確認し、操作の応答を読み取ってください。復元情報はデバイス上に留め、ホストのフォームやログで要求しないでください。

## deviceWipe: デバイスの秘密データを消去 [#devicewipe-erase-private-device-data]

`deviceWipe(connectId)` はデバイスの秘密データを削除し、意図的なユーザー確認が必要です。現在のソースでは Protocol V1 は次を送信します: `WipeDevice`; Protocol V2 はデバイスのリセット設定フローを開きます。プロンプトの表示は完了の証拠ではありません。応答を待ち、キャンセルを処理してください。

消去に成功すると SDK はデバイス状態を無効化します。アプリの選択済みアカウントとウォレット関連付けを破棄し、次の操作前にデバイスを再検出してください。以前の `deviceId` を再利用したり、復元フレーズが残っていると仮定したりしないでください。

両メソッドは SDK の `success` / `payload` レスポンス形式を使います。失敗時に破壊的な操作を自動再試行しないでください。フローを実装する前に [UI イベント処理](/ja/hardware-sdk/core-api-guide#events-ui)と[デバイス識別子](/ja/hardware-sdk/concepts/identifiers)を読んでください。
