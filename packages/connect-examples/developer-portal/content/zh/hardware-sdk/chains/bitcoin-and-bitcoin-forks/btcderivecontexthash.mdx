# btcDeriveContextHash

在设备上为选定的比特币密钥、应用、上下文和网络派生 32 字节的 Babylon 上下文哈希。响应中的 `secret` 是供应用使用的敏感值。

SDK `1.2.8-alpha.6` 已提供此方法。需要 **Classic 1s 或 Classic 1s Pure 固件 3.21.0 及以上版本**，且使用 **Protocol V1**。其他设备系列和 Protocol V2 不支持此方法。

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, params);
```

## 调用示例 [#example]

此代码片段假定 SDK 已初始化，并已选择标准钱包。请将示例中的 `path`、`appName`、`context` 和 `network` 替换为用户授权的值。下方上下文仅为十六进制编码数据的示例。

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, {
  path: "m/84'/0'/0'/0/0",
  appName: 'babylon-example',
  context: '48656c6c6f',
  network: 'bitcoin-mainnet',
  useEmptyPassphrase: true,
});

if (result.success === false) throw new Error(result.payload.error);
const secret = result.payload.secret;
// Use only for the approved application and context. Do not log or persist it.
```

示例通过 `useEmptyPassphrase: true` 明确选择标准钱包。对于隐藏钱包，请传入确认已连接比特币账户时使用的同一个 `passphraseState`。正常的 PIN、passphrase 和设备确认流程仍然适用。

## 错误与敏感值处理 [#errors-and-secret-handling]

无效的 `path`、`appName`、`context` 或 `network` 会在发送派生命令前返回 `CallMethodInvalidParameter`（`405`）。不支持的设备系列或 Protocol V2 返回 `DeviceNotSupportMethod`（`415`）；低于 3.21.0 的固件需要升级。

在设备上取消会返回标准的 `success: false` 响应。停止当前请求，处理 `payload.error` 和 `payload.code` 后，再决定是否重新调用。

SDK 会向应用返回真实的 `secret`。请将其作为敏感值处理，不要写入日志、遥测、剪贴板或持久化存储。派生在设备上执行，内部钱包密钥不会被导出。
