# 从 1.1.x 迁到 1.2.x

给已经接入 Hardware SDK **1.1.x** 的第三方。目标是当前 **1.2.x** 线（npm 稳定版 `1.2.1`）。

JavaScript 方法不用换。Protocol V2（Pro 2 / Neo）在 Core 内部处理。不要再接一套 SDK。

新项目请直接看 [快速开始](/zh/hardware-sdk/getting-started)。

## 什么没变

- 调用形状：`HardwareSDK.method(connectId, deviceId?, params)` → `{ success, payload }`
- 各链方法（`evmGetAddress`、`btcSignTransaction` 等）
- `init({ env })` 仍然选**传输**（USB / BLE / 底层插件），不是 Protocol V1 / V2
- PIN / passphrase / 按键仍走 `UI_EVENT` + `uiResponse`

## 升级包

```bash
npm i @onekeyfe/hd-common-connect-sdk@^1.2.1
```

所有 `@onekeyfe/hd-*` 钉到同一条 1.2.x。如果还在嵌 `@onekeyfe/hd-web-sdk`，**不要传 `connectSrc`**，让 iframe 跟已安装包一致。

不要在同一个运行时里混用 `@onekeyfe/hd-web-sdk` 和 `@onekeyfe/hd-common-connect-sdk`。

## 要替换的 API

| 1.1.x | 1.2.x | 说明 |
| --- | --- | --- |
| `getFeatures()` | [`getDeviceState()`](/zh/hardware-sdk/basic-api/get-device-state) | 读 `payload.identity.deviceId`，不要再用 `payload.device_id` |
| `getOnekeyFeatures()` | `getDeviceState({ scope: 'firmware' })` | 版本 / 身份快照 |
| `getPassphraseState()` | [`openWalletSession({ mode })`](/zh/hardware-sdk/basic-api/open-wallet-session) | 只开一次：`standard` 或 `select-hidden` |
| `keepSession` | **不要改** | 只控制传输持有。不要删掉，也不要用 `passphraseState` / `openWalletSession` 替换。 |
| 把固件 `session_id` 存进库 | **不要存** | Core 内部持有 |
| `env: 'web'` + Bridge | `env: 'webusb'` | 见 [Bridge → WebUSB](/zh/hardware-sdk/legacy-guides/migrate-bridge-to-common-connect-webusb) |
| Pro 2 / Neo 上的 `firmwareUpdateV2` / `V3` | [`firmwareUpdateV4`](/zh/hardware-sdk/device-api/firmwareupdatev4) | Classic / Mini / Touch / Pro 仍用 V2 / V3 |

已废弃方法现有应用还能跑。新代码不要再调。

没有 `openWalletSession({ mode: 'resume-hidden' })`。已经有绑定之后，后续地址 / 签名带上 `passphraseState`，Core 会在方法里恢复。

## 1. 设备快照

**1.1.x**

```ts
const features = await HardwareSDK.getFeatures(connectId);
if (!features.success) throw new Error(features.payload.error);
const deviceId = features.payload.device_id;
```

**1.2.x**

```ts
const state = await HardwareSDK.getDeviceState(connectId);
if (!state.success) throw new Error(state.payload.error);
const deviceId = state.payload.identity.deviceId;
```

`searchDevices` 仍然是 `{ success, payload }`。先看 `success`，再把 `payload` 当设备列表。

## 2. 钱包会话

**1.1.x** — 用 `getPassphraseState` 开隐藏钱包，之后带指纹：

```ts
const ps = await HardwareSDK.getPassphraseState(connectId, {
  initSession: true,
});
const passphraseState = ps.payload;

await HardwareSDK.evmGetAddress(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  passphraseState,
});
```

**1.2.x** — `mode` 开一次，之后方法带指纹：

```ts
import { OpenWalletSessionMode } from '@onekeyfe/hd-core';

// 标准钱包
await HardwareSDK.openWalletSession(connectId, {
  mode: OpenWalletSessionMode.Standard,
});
await HardwareSDK.evmGetAddress(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  useEmptyPassphrase: true,
});

// 隐藏钱包 — 用户在设备上选
const opened = await HardwareSDK.openWalletSession(connectId, {
  mode: OpenWalletSessionMode.SelectHidden,
});
const deviceId = opened.payload.deviceId;
const passphraseState = opened.payload.passphraseState;

await HardwareSDK.evmGetAddress(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  passphraseState,
});
```

不要在同一次 `openWalletSession({ mode })` 上再混 `useEmptyPassphrase` / `initSession`。

隐藏钱包漏传 `passphraseState` 时，地址 / 签名可能在**标准钱包**上成功且不报错。

契约见 [钱包会话](/zh/hardware-sdk/concepts/wallet-session)。

## 3. Protocol V1 与 V2

Classic / Mini / Touch / Pro 仍是 Protocol V1。Pro 2 / Neo 是 Protocol V2。应用仍调同一套方法。

SDK 用**现场探测**写入 `connectProtocol`。不要用 USB PID、蓝牙名或外观判断 V1/V2。

调用上传入 `connectProtocol` 表示严格期望 — SDK 不会悄悄切协议。

仅 V1 的链（Stellar、Alephium、Nexa、Dynex、Nervos、SCDO、Benfen、Neo 链）在 Pro 2 / Neo 上**不支持**。见 [Protocol V1 与 V2](/zh/hardware-sdk/concepts/protocol) 和 [链支持](/zh/hardware-sdk/concepts/chain-support)。

## 4. 固件

| 设备 | 1.2.x API |
| --- | --- |
| Classic / Mini / Touch | `firmwareUpdateV2` |
| Pro | `firmwareUpdateV3` |
| Pro 2 / Neo | `firmwareUpdateV4` |

传输出错后，不要重放固件升级、擦除或签名。

## 5. 传输

如果还在用 OneKey Bridge（`env: 'web'` + `checkBridgeStatus`），迁到 WebUSB：

- 推荐：[Bridge → `@onekeyfe/hd-common-connect-sdk`](/zh/hardware-sdk/legacy-guides/migrate-bridge-to-common-connect-webusb)
- 继续 iframe：[Bridge → `@onekeyfe/hd-web-sdk`](/zh/hardware-sdk/legacy-guides/migrate-bridge-to-webusb)

WebUSB 需要 HTTPS 和用户手势。BLE 需要系统蓝牙权限。

## 检查清单

1. 所有 `@onekeyfe/hd-*` 升到同一条 1.2.x。
2. `getFeatures` / `getOnekeyFeatures` 换成 `getDeviceState`。
3. `getPassphraseState` 换成 `openWalletSession({ mode: 'standard' | 'select-hidden' })`。
4. 只存 `deviceId + passphraseState`。不要再存固件 `session_id`。
5. 之后每笔地址 / 签名带 `passphraseState` 或 `useEmptyPassphrase: true`。
6. USB 连续签名 / 检查后升级、Electron BLE 固件窗口继续保留 `keepSession`。它不是钱包会话标志。
7. 按设备串行调用。
8. 上线 Pro 2 / Neo 前核对链覆盖。
