# btcDeriveContextHash

Deriva en el dispositivo un hash de contexto Babylon de 32 bytes para la clave Bitcoin, la aplicación, el contexto y la red seleccionados. La respuesta contiene un `secret` sensible para que lo utilice tu aplicación.

Disponible en el SDK `1.2.8-alpha.6`. Requiere **Classic 1s o Classic 1s Pure con firmware 3.21.0 o posterior** y **Protocol V1**. Las demás familias de dispositivos y Protocol V2 no son compatibles.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, params);
```

- [Inicializa el SDK y selecciona un dispositivo](/es/hardware-sdk/getting-started).

- Antes de la llamada, obtén la aprobación del usuario para la aplicación solicitante y su origen. El llamante proporciona `appName`; tu aplicación debe determinar qué sitio o aplicación solicita acceso.

## Ejemplo [#example]

Este fragmento presupone un SDK inicializado y una billetera estándar seleccionada. Sustituye los valores de ejemplo `path`, `appName`, `context` y `network` por los aprobados por el usuario. El contexto siguiente es un ejemplo de datos codificados en hexadecimal.

```typescript
const result = await HardwareSDK.btcDeriveContextHash(connectId, deviceId, {
  path: "m/84'/0'/0'/0/0",
  appName: 'babylon-example',
  context: '48656c6c6f',
  network: 'bitcoin-mainnet',
  useEmptyPassphrase: true,
});

if (result.success === false) throw new Error(result.payload.error);
const secret = result.payload.secret;
// Use only for the approved application and context. Do not log or persist it.
```

El ejemplo selecciona explícitamente la billetera estándar con `useEmptyPassphrase: true`. Para una billetera oculta, pasa el mismo `passphraseState` utilizado al confirmar la cuenta Bitcoin conectada. Se mantiene el flujo habitual de PIN, passphrase y confirmación en el dispositivo.

## Respuesta [#result]

## Errores y manejo del secreto [#errors-and-secret-handling]

Un valor no válido de `path`, `appName`, `context` o `network` devuelve `CallMethodInvalidParameter` (`405`) antes de enviar el comando de derivación. Las familias de dispositivos no compatibles o Protocol V2 devuelven `DeviceNotSupportMethod` (`415`); el firmware anterior a 3.21.0 requiere una actualización.

La cancelación en el dispositivo devuelve la respuesta estándar `success: false`. Detén la solicitud y procesa `payload.error` y `payload.code` antes de intentar otra llamada.

El SDK devuelve el `secret` real a tu aplicación. Trátalo como un dato sensible: mantenlo fuera de los registros, la telemetría, el portapapeles y el almacenamiento persistente. La derivación se ejecuta en el dispositivo; la clave interna de la billetera no se exporta.
