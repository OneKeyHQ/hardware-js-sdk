# Compatibilidad de cadenas

Esta página presenta la matriz de **métodos públicos del SDK de hardware**, no la lista de monedas de OneKey App. Las cifras promocionales de la aplicación (100+ cadenas, 30,000+ tokens) describen el catálogo de la cartera. Como integrador, debes contar solo los métodos que puedes llamar en `HardwareSDK`.

Fuente de referencia para Pro 2 / Neo: el método de cada clase Core `getSupportedProtocols()`. De forma predeterminada, solo es compatible con Protocol V1. Una cadena está disponible en Pro 2 / Neo solo cuando el método devuelve `['V1', 'V2']`. Las versiones mínimas de firmware (`min`) pueden quedar obsoletas; consulta la página del método y el firmware del dispositivo, no las copies aquí.

## Salvedades de los dispositivos (pruebas de compatibilidad) [#device-caveats-compatibility-tests]

Estas son combinaciones de método y modelo para las que las pruebas de compatibilidad del repositorio permiten fallos. Se trata de una limitación de la cobertura de pruebas, no del resultado de una prueba reciente con hardware. No anuncies compatibilidad con estas combinaciones sin validar el firmware y el método exactos en el dispositivo.

| Modelo | No des por compatible |
| --- | --- |
| Classic | TON, Alephium, SCDO, Benfen, Neo (cadena), `btcSignPsbt`, `aptosSignInMessage` |
| Classic 1s / Pure | Dynex |
| Mini | Firma de Alephium, firma de Dynex, firma de Neo (cadena), firma de SCDO, firma/prueba de TON, firma de mensajes TRON. **Sin BLE** |
| Touch | Firma de Alephium, firma de Dynex, firma de Neo (cadena), firma de SCDO |
| Pro | Dynex |
| Pro 2 | Métodos de cadena con `['V1', 'V2']` indicados arriba. **Tiene cámara** (Air-Gap) |
| Neo | Los mismos métodos de cadena que Pro 2. **Sin cámara, NFC, lector de huellas ni Find My** — sin QR Air-Gap |

EIP-7702 (`authorizationList`) no es compatible con Classic.

## Función auxiliar de direcciones por lotes [#batch-address-helper]

`allNetworkGetAddress` / `allNetworkGetAddressByLoop` son funciones auxiliares V1+V2. Aun así, fallan en una conexión Protocol V2 si el método propio de la red solo admite V1.

## Derivados de Bitcoin [#bitcoin-forks]

`btc*` aceptan un parámetro `coin` / `coin_name`. La mayoría de los forks siguen la fila de Bitcoin (V1+V2). **Neurai solo admite Protocol V1.**

## Cómo decidir en tiempo de ejecución [#how-to-decide-at-runtime]

`getSupportedProtocols()` es un hook de la clase del método Core, no una llamada pública de `HardwareSDK`. Usa esta página junto con el dispositivo conectado:

1. ¿El SDK exporta el método?
2. ¿El dispositivo tiene `connectProtocol` `'V1'` o `'V2'`?
3. ¿Esta página indica que el método admite V1+V2 o solo V1?
4. ¿Este modelo aparece en la tabla de salvedades?
5. ¿El firmware cumple la versión indicada en la página del método?

No cambies el comportamiento según el PID USB o el nombre BLE. Consulta [Protocol V1 y V2](/es/hardware-sdk/concepts/protocol) y [Dispositivos](/es/hardware-sdk/concepts/devices).
