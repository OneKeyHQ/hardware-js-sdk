# deviceSettings

## Device settings

Modify one property per call. For Pro2 Passphrase and Air-gap settings, the boolean is the target
state; the actual toggle happens on the device settings page and requires a second confirmation.

```typescript
const result = await HardwareSDK.deviceSettings(connectId, params);
```

## Params

[**Optional common params**](/en/hardware-sdk/core-api-guide#common-params)

* `language` - _optional_ `string` Device language, [ISO 639-1 codes](https://en.wikipedia.org/wiki/List\_of\_ISO\_639-1\_codes)
* `label` - _optional_ `string` Device name
* `usePassphrase` - _optional_ `boolean` Open passphrase or not
* `airgapMode` - _optional_ `boolean` Enable Air-gap mode (Protocol V2 / Pro2 only)
* `homescreen` - _optional_ `string` Change homescreen by hex string
* `autoLockDelayMs` - _optional_ `number` Auto lock time in ms
* `displayRotation` - _optional_ `number` In degrees from North
* `passphraseAlwaysOnDevice` - _optional_ `boolean` Do not prompt for passphrase, enforce device entry
*   `safetyChecks` - _optional_ `number` Protocol V1 safety check level

    0: Strict
    1: PromptAlways
    2: PromptTemporarily

* `experimentalFeatures` - _optional_ `boolean` Enable experimental message types

## Protocol V1 / V2 behavior

* Protocol V1 sends the `usePassphrase` target through `ApplySettings`, preserving the existing behavior.
* Protocol V2 / Pro2 `DeviceSettingsPageShow` does not accept a target boolean. The SDK reads the current
  state first. If it already matches, the call is a no-op; otherwise the SDK opens the corresponding
  device page, waits for the on-device toggle and confirmation, then reads the state again to verify it.
* On Protocol V2, do not combine `usePassphrase` or `airgapMode` with direct settings in one call.
  This avoids partial success across an interactive device transaction and a direct settings write.
* Use `getDeviceSettingsCapabilities(deviceType, protocol)` for supported fields, languages, ranges,
  and timeout values. Protocol V2 uses `0x10000000` for the Never timeout; Protocol V1 uses `0`.
* Raw `deviceSettingsGet`, `deviceSettingsSet`, and `deviceSettingsPageShow` methods are not public APIs.

## Example

```typescript
HardwareSDK.deviceSettings(connectId, {
    label: 'My OneKey Wallet'
});
```

```typescript
// Pro2: request the Air-gap target state; the SDK decides whether to open the device page.
HardwareSDK.deviceSettings(connectId, {
    airgapMode: true
});
```

## Result

```typescript
{
    success: true,
    payload: {
        message: string
    }
}
```

Error

```typescript
{
    success: false,
    payload: {
        error: string, // error message
        code: number // error code
    }
}
```
