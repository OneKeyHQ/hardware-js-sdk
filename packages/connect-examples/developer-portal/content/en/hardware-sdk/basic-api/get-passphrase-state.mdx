# Get Passphrase State

## Get the passphraseState of the device

Prompts the user to enter their passphrase (on-device or via software), then returns a `passphraseState` string — the public hidden-wallet fingerprint. Persist `deviceId + passphraseState`. Do not persist firmware `session_id`.

New integrations should prefer [`openWalletSession`](/en/hardware-sdk/basic-api/open-wallet-session). This method remains the compatibility entry on Hardware SDK 1.2.0 (Protocol V1 and V2). See [Wallet Sessions](/en/hardware-sdk/concepts/wallet-session).

Pass `passphraseState` on later address / signing calls so they stay on that hidden wallet. It is a **wallet fingerprint**, not firmware `session_id`. Do not persist `session_id`.

```
  getPassphraseState(connectId)   ← user enters passphrase once
    → passphraseState = "<fingerprint>"

  evmGetAddress(..., { passphraseState })
  btcGetAddress(..., { passphraseState })
```

> **Error 112 (passphrase state mismatch)**: the binding does not match the wallet currently unlocked (device locked, seed changed, or stale fingerprint). Call `getPassphraseState` / `openWalletSession` again, then retry. `skipPassphraseCheck: true` skips this check and emits `REQUEST_PASSPHRASE` instead.

```typescript
const response = await HardwareSDK.getPassphraseState(connectId);
```
