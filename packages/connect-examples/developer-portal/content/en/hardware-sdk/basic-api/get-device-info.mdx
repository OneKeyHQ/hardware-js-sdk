# Get Device State

`getDeviceState` is the canonical device information API for Protocol V1 and Protocol V2 devices. Integrations consume the same `DeviceState` shape for Pro, Pro2, Classic, Mini, and Touch devices; protocol-specific messages remain inside the SDK.

```typescript
const response = await HardwareSDK.getDeviceState(connectId);
```

The default call returns the current snapshot and performs only the minimum initialization when no snapshot exists. For Pro2, initialization reads `DeviceInfoGet` without a status target and does not call `DeviceStatusGet`.

## Explicit refresh

Use a semantic business scope when hardware synchronization is required:

```typescript
const versions = await HardwareSDK.refreshDeviceState(connectId, {
  scope: 'firmware',
});

const runtimeStatus = await HardwareSDK.refreshDeviceState(connectId, {
  scope: 'runtime',
});
```

Available scopes are `basic`, `firmware`, `settings`, and `runtime`. A `runtime` or `settings` refresh in bootloader/romloader mode returns an unsupported-operation error instead of silently returning stale fields.

## State sections

The returned snapshot contains:

- `identity`: device type, IDs, serial number, label, BLE name, and `displayName`.
- `status`: mode, initialization, lock, backup, PIN, and passphrase state.
- `settings`: language, display, security, BLE, and Pro2 preferences.
- `versions`: firmware, bootloader, board, BLE, and secure-element versions.
- `verification`: build IDs and hashes when explicitly refreshed.
- `session`: volatile session data.
- `raw`: SDK-internal protocol diagnostics used by the Protocol V1 compatibility projector; public `getDeviceState` does not expose it.

Visible device names should use `state.identity.displayName`, whose priority is `label`, then `bleName`, then the model display name.

## Events

Subscribe to `DEVICE.STATE` for updates. Settings and rename operations update the SDK snapshot first and then emit the full state, so callers do not need an extra read after a successful mutation.

```typescript
HardwareSDK.on(DEVICE.STATE, ({ state, revision }) => {
  renderDevice(state.identity.displayName);
  persistIfNewer(state, revision);
});
```

`getFeatures` and `DEVICE.FEATURES` remain only for Protocol V1 compatibility. `getDeviceInfo`, `deviceInfoGet`, `deviceStatusGet`, and `deviceSettingsGet` are not public APIs.
