# Open Wallet Session

Unified Protocol V1 / V2 entry to open the standard wallet, let the user select a hidden wallet, or resume a hidden wallet you already bound.

New integrations should use this method at the "open / switch wallet" step. Address and signing calls still take `deviceId` + `passphraseState` and should not reopen a session every time.

See [Wallet Sessions](/en/hardware-sdk/concepts/wallet-session) for the contract.

```ts
import { OpenWalletSessionMode } from '@onekeyfe/hd-core';

const res = await HardwareSDK.openWalletSession(connectId, {
  mode: OpenWalletSessionMode.Standard,
});
```

### Params

[Optional common params](/en/hardware-sdk/concepts/common-params)

Do not combine `mode` with `useEmptyPassphrase` or `initSession` on this call.

| Param | Type | Required | Notes |
| --- | --- | --- | --- |
| `mode` | `'standard' \| 'select-hidden' \| 'resume-hidden'` | Yes | Use `OpenWalletSessionMode` from `@onekeyfe/hd-core` |
| `deviceId` | `string` | `resume-hidden` only | Seed lifetime from a previous successful open |
| `passphraseState` | `string` | `resume-hidden` only | Hidden-wallet fingerprint from a previous successful open |

### Result

```ts
{
  success: true,
  payload: {
    protocol: 'V1' | 'V2',
    deviceId: string,
    resumed: boolean,
    walletType: 'standard' | 'hidden',
    passphraseState: string | null, // null on standard wallet
  }
}
```

Persist `deviceId`, `walletType`, and `passphraseState`. The firmware `session_id` is not returned.

### Error

```ts
{
  success: false,
  payload: {
    error: string,
    code: number,
  }
}
```

Missing `deviceId` / `passphraseState` on `resume-hidden` returns `CallMethodInvalidParameter`. A hidden wallet that cannot be resumed safely may return `WalletSessionInvalid` (Protocol V1) or complete a re-select inside the same call (Protocol V2). `DeviceCheckUnlockTypeError` means the current PIN / Attach-to-PIN context cannot reach the requested wallet.
