# AI Agent Integration

OneKey publishes a suite of **wallet skills** that let AI coding assistants (Claude Code, Cursor, Codex, OpenCode, OpenClaw, …) perform real wallet operations on your behalf — balance, transfer, swap, market research, token security audit — all backed by your choice of wallet, including a OneKey **hardware wallet**.

Skills and install flows live in the dedicated repo:

👉 **[OneKeyHQ/onekey-wallet-skills](https://github.com/OneKeyHQ/onekey-wallet-skills)**

## Skills

Four domain-scoped skills:

| Skill | What it does |
|---|---|
| **onekey-wallet** | Balance, portfolio, transfer, history, import / logout |
| **onekey-swap** | Swap quote, execution, cross-chain bridge, status |
| **onekey-market** | Token prices, trending, K-line, liquidity, holders, research |
| **onekey-security** | Token audit, honeypot check, transaction simulation |

Every skill drives the `onekey` CLI (npm package [`@onekeyfe/cli`](https://www.npmjs.com/package/@onekeyfe/cli)). The skill auto-installs the CLI on first use (`npm install -g @onekeyfe/cli`) — you don't need to install it separately.

## Installation

### Claude Code

Claude Code's plugin marketplace handles everything:

```text
/plugin marketplace add OneKeyHQ/onekey-wallet-skills
/plugin install onekey-wallet-skills
```

### Cursor

Clone the repo and point Cursor at the plugin directory (`.cursor-plugin/plugin.json`):

```bash
git clone https://github.com/OneKeyHQ/onekey-wallet-skills
```

### Codex CLI

Tell Codex:

```text
Fetch and follow instructions from https://raw.githubusercontent.com/OneKeyHQ/onekey-wallet-skills/main/.codex/INSTALL.md
```

## Using a OneKey hardware wallet

At login, pick hardware as the wallet kind — this is the **only** place `--hardware` appears:

```bash
onekey auth login --hardware
```

The CLI walks you through device discovery, PIN entry (on device), and passphrase (if enabled). See [PIN Code](/en/hardware-sdk/concepts/pin) and [Passphrase](/en/hardware-sdk/concepts/passphrase) for those flows.

After `login`, **every** subsequent skill-driven command goes through the hardware wallet automatically. Don't pass `--hardware` on business commands — the flag lives only on `auth login`:

```bash
# Once: login with hardware
onekey auth login --hardware

# Then: the skills call these directly; you don't pass --hardware again
onekey balance --chain eth
onekey transfer --chain eth --to 0x... --amount 0.01
onekey swap --from eth --to usdc --amount 0.5
onekey history --chain eth
```

Log out when done:

```bash
onekey auth logout
```

## Output format

Every skill command returns structured JSON suitable for programmatic consumption:

```json
{
  "status": "success",
  "api_version": "1",
  "data": { "...command-specific..." },
  "metadata": { "timestamp": "2026-04-19T..." }
}
```

On failure the envelope stays the same with `status: "error"` plus a typed error `code` and `message`.

## Hardware-only alternative

For **hardware-only** workflows that skip the `onekey` account layer entirely — direct device management, raw signing from a CI pipeline, narrow agent skills focused on device protocol — the separate [`@onekeyfe/hardware-cli`](https://www.npmjs.com/package/@onekeyfe/hardware-cli) (`onekey-hw`) package stays available. It's narrower but requires no account login; just plug in the device and run `onekey-hw`.

```bash
npm install -g @onekeyfe/hardware-cli
onekey-hw search
onekey-hw get-address --chain evm --use-empty-passphrase
```

Use `@onekeyfe/cli` + skills for end-user-style agent workflows; use `@onekeyfe/hardware-cli` when you only need the hardware protocol.
