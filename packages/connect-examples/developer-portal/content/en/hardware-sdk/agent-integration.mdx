# AI Agent Integration

`@onekeyfe/hardware-cli` enables AI agents to interact with OneKey hardware wallets via USB.

Skills follow the [Agent Skills](https://agentskills.io) open standard, supported by 30+ tools including Claude Code, Codex, Gemini CLI, GitHub Copilot, Cursor, and JetBrains.

## Install CLI

```bash
npm install -g @onekeyfe/hardware-cli
```

## Install Skills (Universal)

Works with all Agent Skills compatible tools (30+):

```bash
npx skills add OneKeyHQ/hardware-js-sdk
```

This auto-detects your tool (Claude Code, Codex, Gemini, Cursor, etc.) and installs skills to the correct location.

## Schema Discovery

After installing the CLI, you can explore all available commands and their parameters using the built-in schema system:

```bash
# List all available commands with descriptions
onekey-hw schema list

# Show full schema for a specific command (parameters, types, examples)
onekey-hw schema get-address
onekey-hw schema sign-transaction
```

This is especially useful for AI agents to dynamically discover supported commands and construct valid invocations without hardcoded knowledge.

## Claude Code

```bash
claude plugin marketplace add OneKeyHQ/hardware-js-sdk --sparse .claude-plugin packages/hd-cli
claude plugin install onekey-hardware@onekey-hardware-plugins
```

The CLI is installed automatically on first use via the skill's pre-flight check.

## Usage

### Standard wallet (no passphrase)

Use `--use-empty-passphrase` on every command to target the standard wallet.

```bash
# Search for connected devices (auto-fetches device info)
onekey-hw search

# Get an Ethereum address
onekey-hw get-address --chain evm --use-empty-passphrase

# Get a Bitcoin address
onekey-hw get-address --chain btc --use-empty-passphrase

# Sign a message
onekey-hw sign-message --chain evm --message "hello" --use-empty-passphrase

# Sign an EVM transaction
onekey-hw sign-transaction --chain evm \
  --tx '{"to":"0x...","value":"0xf4240","chainId":1,"nonce":"0x0","gasLimit":"0x5208","gasPrice":"0xbebc200"}' \
  --use-empty-passphrase

# Check firmware
onekey-hw firmware-check-all
```

### Hidden wallet (passphrase-protected)

Hidden wallets require a two-step flow. Obtain `passphraseState` once per session, then use it on all subsequent commands — no passphrase re-entry needed.

```bash
# Step 1: Get passphraseState (prompts passphrase on device once)
# --passphrase can be omitted to enter on the device screen (Pro/Touch)
onekey-hw passphrase-state --passphrase "mypassphrase" --connect-id <id>
```

The output includes a `passphrase_state_ready` event on stderr:

```json
{"event":"passphrase_state_ready","detail":{"passphraseState":"abc123...","usage":"..."}}
```

Extract `detail.passphraseState` and use it alongside `--passphrase` on all subsequent commands:

```bash
# Step 2: All subsequent commands — use BOTH --passphrase AND --passphrase-state
onekey-hw get-address --chain evm --passphrase "mypassphrase" --passphrase-state abc123... --connect-id <id>
onekey-hw get-address --chain btc --passphrase "mypassphrase" --passphrase-state abc123... --connect-id <id>
onekey-hw batch-get-address --bundle '[...]' --passphrase "mypassphrase" --passphrase-state abc123... --connect-id <id>
onekey-hw sign-transaction --chain evm --tx '...' --passphrase "mypassphrase" --passphrase-state abc123... --connect-id <id>
```

> **Why `--passphrase` is always required**: The CLI is stateless — each invocation is a new process with no session cache. The device always requests passphrase on a fresh connection. `passphraseState` is a wallet fingerprint (validator) that ensures you always access the same hidden wallet, but it does not replace passphrase entry.

**Simpler (no validation):** just use `--passphrase "mypassphrase"` directly without the `passphrase-state` step.

> **Error 112 (Device passphrase state error)**: Session expired — re-run `passphrase-state` to obtain a fresh state value, then retry.

> **Never combine** `--use-empty-passphrase` with `--passphrase` or `--passphrase-state`.

Firmware updates must be done via the [OneKey App](https://onekey.so/download) or [firmware.onekey.so](https://firmware.onekey.so/).

## Programmatic Integration (HardwareSigner)

For TypeScript/JavaScript applications, you can use `createHardwareSigner` to interact with OneKey hardware wallets programmatically:

```typescript
import { createHardwareSigner } from '@onekeyfe/hardware-cli';

// Create signer (initializes SDK + USB transport)
const signer = await createHardwareSigner({ useEmptyPassphrase: true });

try {
  // Get an Ethereum address
  const { address, path } = await signer.getAddress('evm');
  console.log(address); // 0x3611...

  // Sign a transaction
  const signed = await signer.signTransaction('evm', {
    to: '0x1234...',
    value: '0xf4240',
    chainId: 1,
    nonce: '0x0',
    gasLimit: '0x5208',
    gasPrice: '0xbebc200',
  });

  // Sign a message
  const { signature } = await signer.signMessage('evm', 'hello');
} finally {
  // Always dispose to release USB connection
  signer.dispose();
}
```

`createHardwareSigner` wraps the CLI's transport and SDK layers, providing a typed async API suitable for agent frameworks, backend services, and automation scripts.
