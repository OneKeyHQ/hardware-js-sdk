# Hardware SDK Core API Guide

Lifecycle how-to: init → search → events → first protected call → cleanup.

Parameter tables live in [Common Params](/en/hardware-sdk/concepts/common-params). Device and protocol differences live in [Devices](/en/hardware-sdk/concepts/devices) and [Protocol V1 and V2](/en/hardware-sdk/concepts/protocol).

## Quick flow
<div id="request-basics" />

- Call shape: `HardwareSDK.method(connectId, deviceId?, params)` → `Promise<{ success, payload }>`; always guard on `success` before touching `payload`.
- Identifiers: `connectId` from `searchDevices`; `deviceId` from `getDeviceState` (required for BLE, recommended for WebUSB). Refresh `deviceId` after reset/recovery. Full table: [Identifiers](/en/hardware-sdk/concepts/identifiers).
- UI contract: subscribe `UI_EVENT` once; only call `uiResponse` on input-type `UI_REQUEST` (PIN / Passphrase / Bootloader select). Route per device when several devices are connected.
- Serialize calls per device. Reuse a hidden wallet with `openWalletSession` (or `initSession + passphraseState` on the compatibility path).

```ts
const res = await HardwareSDK.evmGetAddress(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  useEmptyPassphrase: true,
});

if (!res.success) throw new Error(res.payload.error);
console.log(res.payload.address);
```

## Core identifiers & environments

| ID | Purpose | Obtain via | Changes when |
| --- | --- | --- | --- |
| `connectId` | Which connection | `searchDevices()` | USB re-plug, BLE re-pair, transport switch |
| `deviceId` | Which seed lifetime | `getDeviceState` (`getFeatures` is deprecated) | Wipe, recovery, seed switch |

USB and BLE `connectId` values for the same unit are different — cache them separately. See [Identifiers](/en/hardware-sdk/concepts/identifiers) and [Reconnect and dispose](/en/hardware-sdk/transport/reconnect).

**Runtime requirements**

- `webusb` — HTTPS + user gesture.
- `react-native` — BLE entitlement + (commonly) location permission.
- `lowlevel` — 64-byte frame adapter on the host.
- Firmware — some APIs fail in Bootloader.

### Which identifiers are required?

| Requirement | Description | Example APIs |
| :--- | :--- | :--- |
| 🟢 No identifiers | SDK init, config, event management | `init` `on/off` `searchDevices` `getLogs` `dispose` `uiResponse` |
| 🟡 `connectId` only | Device management, status, firmware ops | `getDeviceState` `openWalletSession` `cancel` `deviceSettings` |
| 🔵 `connectId` + `deviceId` | Blockchain signing, address, encryption | `evmSignTransaction` `btcSignTransaction` `solanaSignMessage` `allNetworkGetAddress` |

## Standard lifecycle (recommended)
<div id="standard-lifecycle" />

`init → search → getDeviceState → subscribe UI/DEVICE/FIRMWARE → call + uiResponse → cleanup`

```ts
import HardwareSDK, { UI_EVENT, UI_REQUEST, UI_RESPONSE } from '@onekeyfe/hd-common-connect-sdk';

await HardwareSDK.init({ env: 'webusb', fetchConfig: true, debug: false });

const devices = await HardwareSDK.searchDevices();
if (!devices.success || !devices.payload.length) throw new Error('No device');
const { connectId } = devices.payload[0];

const state = await HardwareSDK.getDeviceState(connectId);
if (!state.success) throw new Error(state.payload.error);
const deviceId = state.payload.identity.deviceId;

HardwareSDK.on(UI_REQUEST.REQUEST_PIN, () => {
  // open UI, collect input, then uiResponse
});
HardwareSDK.on(UI_REQUEST.REQUEST_PASSPHRASE, () => {});

await HardwareSDK.evmSignTransaction(connectId, deviceId, {
  path: "m/44'/60'/0'/0/0",
  useEmptyPassphrase: true,
});
```

Serialize per device. Refresh features after a device switch. Remove listeners on unmount. Call `HardwareSDK.dispose()` only when tearing down the transport — see [Reconnect and dispose](/en/hardware-sdk/transport/reconnect).

## Events & UI wiring
<div id="events-ui" />

Subscribe once near app start. Only call `uiResponse` for input requests.

**UI requests that require `uiResponse`**

| UI_REQUEST | When it fires | Respond with |
| --- | --- | --- |
| `REQUEST_PIN` | Protected call on a locked device | `UI_RESPONSE.RECEIVE_PIN` |
| `REQUEST_PASSPHRASE` | Hidden wallet via software input | `UI_RESPONSE.RECEIVE_PASSPHRASE` |
| `REQUEST_PASSPHRASE_ON_DEVICE` | Hidden wallet on device | `UI_RESPONSE.RECEIVE_PASSPHRASE` (`passphraseOnDevice: true`) |
| `REQUEST_DEVICE_IN_BOOTLOADER_FOR_WEB_DEVICE` | Web Bootloader chooser | `UI_RESPONSE.SELECT_DEVICE_IN_BOOTLOADER_FOR_WEB_DEVICE` |

**UI notifications (no `uiResponse`)**

| UI_REQUEST | Purpose |
| --- | --- |
| `REQUEST_BUTTON` | Confirm on device. Firmware update uses `reason='firmware-update'` — still no `uiResponse` |
| `DEVICE_PROGRESS` | Long-running task progress |
| `FIRMWARE_PROCESSING` / `FIRMWARE_PROGRESS` / `FIRMWARE_TIP` | Firmware upgrade states |
| `BLUETOOTH_PERMISSION` / `LOCATION_PERMISSION` | BLE permission prompts |
| `BOOTLOADER` / `REQUIRE_MODE` / `NOT_INITIALIZE` / `FIRMWARE_NOT_SUPPORTED` | Mode or support hints |

**Device / firmware events**

| Channel | Event | Typical handling |
| --- | --- | --- |
| `DEVICE_EVENT` | `CONNECT` | Refresh device list |
| `DEVICE_EVENT` | `DISCONNECT` | Invalidate the connection; do not replay side-effecting calls. [Reconnect](/en/hardware-sdk/transport/reconnect) |
| `DEVICE_EVENT` | `ACQUIRE` / `RELEASE` | Gate concurrent calls |
| `DEVICE_EVENT` | `CHANGED` | Re-read `getDeviceState` |
| `DEVICE_EVENT` | `USED_ELSEWHERE` | Close the other Bridge / tab |
| `FIRMWARE_EVENT` | `RELEASE_INFO` / `BLE_RELEASE_INFO` | Offer upgrade when safe. [Firmware Update](/en/hardware-sdk/firmware-update) |

```ts
import HardwareSDK, { UI_EVENT, UI_REQUEST, UI_RESPONSE } from '@onekeyfe/hd-common-connect-sdk';

const handleUiEvent = (msg) => {
  switch (msg.type) {
    case UI_REQUEST.REQUEST_PIN:
      openPinModal(({ value }) =>
        HardwareSDK.uiResponse({ type: UI_RESPONSE.RECEIVE_PIN, payload: value })
      );
      return;
    case UI_REQUEST.REQUEST_PASSPHRASE:
      openPassphraseModal(({ value, onDevice, save }) =>
        HardwareSDK.uiResponse({
          type: UI_RESPONSE.RECEIVE_PASSPHRASE,
          payload: { value, passphraseOnDevice: onDevice, attachPinOnDevice: false, save },
        })
      );
      return;
    default:
      break;
  }
};

HardwareSDK.on(UI_EVENT, handleUiEvent);
```

## Errors
<div id="error-codes" />

| Group | Common causes | Recommended actions |
| --- | --- | --- |
| Device (101–118, 200) | Wrong mode, busy, `deviceId` mismatch, not initialized | Confirm mode, reconnect, re-run `init` + `getDeviceState` |
| IFrame (300–305) | Init missing, load/timeout/blocked | Ensure `init` succeeded; check CSP / iframe |
| Method/Firmware (400–418) | Bad params, firmware required, forbidden path | Validate HD path; [Firmware Update](/en/hardware-sdk/firmware-update) |
| Transport (600–603) | Transport not configured, concurrent call | Check `env`, serialize calls |
| Bluetooth (700–722) | Scan/permission/connect/timeout | Permission, proximity; do not loop on a stale bond |
| Runtime/Bridge (800–821) | PIN cancelled, Bridge timeout | Retry or start Bridge |
| Web device (901–902) | WebUSB not authorized | HTTPS + user gesture |

Map `payload.code`, not `payload.error` text. Definitions: [`HardwareError.ts`](https://github.com/OneKeyHQ/hardware-js-sdk/blob/onekey/packages/shared/src/HardwareError.ts).
